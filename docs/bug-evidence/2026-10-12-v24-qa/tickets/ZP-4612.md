# ZP-4612 — Asset editor saves only changed fields; change-history noise filter, paging, and COM last-assessed accuracy (Task #92)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, migration, ui

## Description

### What's the problem

On the web, the unified editor PUT its entire form on every save, so renaming an asset re-sent COM, location, and library fields. That overwrote other users' newer saves, falsely re-stamped the COM 'last assessed' timestamp, and wrote stale display snapshots (e.g. location 'Unassigned' pulled from a grid row) back to the database.

The asset change history then churned with noise: the legacy nodes.location free-text column (dead for \~12 months, superseded by rooms) was rewritten on every save; COM 'modified at/by' was re-stamped whenever com_calculation was merely present in the payload; and empty-to-empty changes plus internal \*\_modified_at/\_by bookkeeping stamps were all recorded. Assets with thousands of changes also had no index-backed paging.

### What's the solution

The editor now sends only fields that differ from the load-time payload (id/value lists compared order-free by id, empties treated as equal, a class change carries node_terminals, save-time overrides always sent; no baseline -> full payload).

The backend stops writing the legacy nodes.location column entirely - a 'location' key from any client is ignored, so every client stops at once without an app release, while existing values stay readable for the legacy room-less fallbacks. COM 'last assessed' is stamped only when com_calculation actually changes. Change-history noise is filtered (skip \*\_modified_at/\_by and \*\_updated_at/\_by; None / '' / \[\] / {} compare equal). GET /entity-history gains server-side paging (100/page, max 500) plus hide_geometry and field filters, backed by a new index via migration ehist_a2. The history dialog adds a default-on 'Hide position changes' toggle and a field filter. Caveat: frontend #1640 depends on backend #1454.

### Fixes

* eg-pz-backend #1454 - Task #92: COM 'last assessed' stamps only real changes; history noise filter, paging index, filters
* eg-pz-backend #1455 - Task #92: stop writing the legacy nodes.location free-text column

### QA Review

Environment: dev only.

* On dev, open an asset, rename it, and save. Confirm the COM 'last assessed' (modified at/by) is unchanged and the change history shows only the name change - no location or COM entries.
* Edit a single asset attribute; confirm the change history records just that field, not the whole attribute list, and position/geometry entries are hidden by default.
* In the history dialog, toggle 'Hide position changes' off and use the field filter; confirm the server-side filtering returns the expected rows and paging works on an asset with many changes (migration ehist_a2 applied).
* Edit the same asset in two tabs; confirm saving a rename in one no longer overwrites an unrelated field saved in the other.
* Negative: send a 'location' value from any client and confirm it is ignored (nodes.location not written) while existing location values still display in session/quote/lookup fallbacks.

### Migration - needs review

ehist_a2 adds index (entity_type, entity_id, id DESC) and replaces the prior changed_at index; the endpoint orders/pages by id.

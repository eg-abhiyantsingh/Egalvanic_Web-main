# ZP-4511 — Journal review: accepting a walk ends interpretation, enclosures render as boxes, and the engine's liberty rule claims unnamed feeders

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, ui

## Description

### What's the problem

Two journal-review problems shipped together. (1) Re-reading a journal walk after Accept laid a second copy of the whole interpreted tree beside the accepted one - two Re-interpret clicks produced 38 accepted units plus 38 proposed units - because Accept only cleared is_proposed and a re-run retired only still-proposed rows, so nothing accepted was retired. (2) On the review graph an enclosure (e.g. a switchboard with twelve 3-pole feeders) drew as one bubble fanning lines to twelve child bubbles, and the engine's derived board->feeder containment edges reached the graph as feed arrows, so containment looked identical to a real feed. (3) In the interpretation engine, feeds leaving a board that had only unnamed breakers ('which of the 12?') stayed on the board and nothing owned them.

### What's the solution

Backend (#1403): removed POST /site-walk/<id>/interpret; Accept now ends the reading (sets auto_interpret=false, clears interpretation_requested_at); the entry sweeper skips a walk that already holds accepted interpreted rows; a run that finishes after acceptance is not applied (result kept, proposed counts 0); /interpret/status now carries 'accepted'. No migration. Pipeline (#135): the 'liberty rule' - a feed leaving a board that still has unnamed feeders claims one (a feeder named for that load first, else the next unclaimed one in walk order), labels it with the load and leaves the feed from the breaker; containment (parent_ref + side) is no longer emitted as a connection; prompt updated; FOLD_VERSION -> 2026-09-30.1 so every cached fold re-folds once. Frontend (#1586): a device with children draws as a rounded box with its breakers in a row inside (ordered by load), board->own-child and main->own-board rows are never drawn, and the Re-interpret button + interpretSiteWalk are removed (controls show Interpreting / 'Accepted - no longer read' / Accept). Caveat: the liberty rule's breaker choice among unnamed feeders is deliberately arbitrary and never invents a device.

### Fixes

* eg-pz-backend #1403 - Journal walks: accepting ends the interpretation; the explicit re-read is gone
* eg-pz-frontend #1586 - UI Journal review: enclosures draw as boxes with their breakers inside; Re-interpret button removed
* eg-pz-engineering-ai-pipeline #135 - Journal engine: the liberty rule (feeds claim unnamed feeders), containment stays containment; fold Lambda: a fold that missed a photo is not cached

### QA Review

Environment: dev only.

* Interpret a journal walk and Accept it: confirm there is no Re-interpret button and the controls read 'Accepted - no longer read'; re-open the walk and confirm the accepted tree is NOT duplicated (no second copy of units).
* Interpret a walk containing an enclosure/board with several feeders: confirm it renders as a rounded box with the breakers in a row inside and feeds dropping from each breaker to its load, with no 'board -> its own breaker' arrows.
* Confirm a board described with only unnamed breakers (e.g. 'three sections, four 400A breakers each') has its outgoing feeds attached to individual breakers (labelled by load), not left on the board, with one warning per board listing the assignments.
* Negative: a feeder already named for something else is not reused for another load.
* Note: every walk re-folds once due to the FOLD_VERSION bump.

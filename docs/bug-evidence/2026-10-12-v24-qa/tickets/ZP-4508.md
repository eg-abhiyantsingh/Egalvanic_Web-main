# ZP-4508 — Journal interpretation: walk-wide fold engine + SQS/Lambda runner (behind JOURNAL_RUNNER, default sfn)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, schema

## Description

### What's the problem

Journal interpretation - the AI that turns a technician's talk-and-shoot site walk into a proposed equipment tree - ran one Fargate task per change through a Step Function: 50-70 seconds of wall time for 0.1-16 seconds of actual model work, so every save a technician made cost about a minute.

Two accuracy problems compounded the slowness. Each room was folded in isolation and a separate reconcile pass - which fired on zero measured runs - was meant to stitch rooms together, so cross-room references and cross-room feeds were lost. And counted groups collapsed into a single asset with a quantity, so "a switchboard feeding four transformers" could never become four distinct nodes with four feeds. The per-entry cache also stored the whole walk state, growing quadratically on a long walk.

### What's the solution

Reworked the journal engine to a walk-wide fold and added an SQS/Lambda runner as an opt-in alternative to the Step Function:

* Walk-wide fold: every entry is folded in arrival order into ONE walk state; the model sees the current room in full plus a compact index of the rest of the site, so cross-room references, implied-then-real equipment and cross-room feeds resolve in the fold. The separate reconcile stage and its prompts are removed.
* One device, one node: quantity N expands deterministically into N units (group_id/size/index) and feeds fan out per unit; stored quantity is always 1. Group labels preserved verbatim.
* Feeds attach to the most specific existing node: a mentioned three-phase main becomes a 3-pole line-side node carrying the rating; feeder breakers carry their circuit; 1P/2P branch breakers are not nodes so the panel is the endpoint. Feed resolution never creates nodes and warns the reviewer when it fires.
* New journal-fold-lambda: an SQS FIFO consumer (one message group per walk) that reads the walk with the read-only DB user, folds with the vendored engine and writes status/states/latest/preview/assembly under journal-jobs/{job_id}/. It checkpoints and re-sends itself near the deadline, honours a cancel marker, and follows AI_WORKHORSE_MODEL. Cache reduced to per-entry chain hashes + one latest state.
* Backend gains JOURNAL_RUNNER=sfn|sqs|local (default sfn) and JOURNAL_FOLD_QUEUE_URL; in sqs mode start() sends one FIFO message per run, poll() reads status.json from S3, and kill() writes a cancel marker.

**Caveat: nothing switches over on merge. The backend stays on sfn until an environment is explicitly flipped, so this merge changes no running environment.**

### QA Review

Environment: Dev only (not yet promoted to QA). Dev runs the new engine on the SQS path only if JOURNAL_RUNNER=sqs has been set on dev; otherwise the reworked engine code is present but the Step Function path still runs.

* Run a multi-room journal site walk that mentions the same equipment across rooms (e.g. "the transformer in the other room") and confirm the cross-room reference resolves to one node, not two.
* Enter a counted group ("a switchboard feeding four transformers") and confirm it expands to four separate transformer nodes with four feeds, not one asset with quantity 4.
* Confirm a three-phase main is created as a 3-pole line-side node carrying the rating, while 1P/2P branch breakers do not become nodes (panel is the endpoint).
* Confirm no reconcile pass runs and interpretation latency drops from \~50-70 s toward a few seconds per fold.
* Verify a mid-walk save is picked up (checkpoint / hash-only-prefix resume) and that cancelling a run writes and honours the cancel marker.
* Negative case: with JOURNAL_RUNNER=sfn (the default), confirm behaviour is unchanged and the Step Function path still works - merging must not alter any un-flipped environment.

### Rollout - needs the pipeline bootstrap per environment first

CI only updates the Lambda image; it does not create the queue or the function. To flip an environment to the queue: (1) run infra/bootstrap_journal_fold.sh <env> (creates the FIFO queue + DLQ, Lambda 2 GB/900 s, role, event-source mapping, DLQ alarm; idempotent), (2) promote the pipeline branch, (3) set JOURNAL_RUNNER=sqs and JOURNAL_FOLD_QUEUE_URL on eg-pz-<env>-be-td-ohio and grant the backend task role sqs:SendMessage on the queue, (4) run one journal walk end to end. Dev was bootstrapped 2026-09-29; qa / staging / prod / bces-iq are NOT yet bootstrapped - do each right before its promotion. Full steps in the pipeline PR's infra/RUNBOOK.md.

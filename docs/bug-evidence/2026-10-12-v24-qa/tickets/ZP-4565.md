# ZP-4565 — Maintenance Portal nav section gated to Portal Sales only; Site Data > Maintenance rides the LaunchDarkly company flag (task #51)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: frontend, ui

## Description

### What's the problem

The 2026-09-08 narrowing of the Maintenance Portal to the Portal Sales role only reached the route guard and the item locks, never the nav rail section itself: the section's requiresTier2 still exempted Project Manager / Account Manager / Admin / Facility Manager / Super Admin as a "preview". On 2026-09-30 a staff user without Portal Sales was reported still seeing the Maintenance Portal section. Separately, the company flag meant to govern Site Data > Maintenance only disabled Maintenance Program (ZP-4326), while Compliance and Reports listed for every company.

### What's the solution

Two independent gates, LaunchDarkly only. The frontend no longer reads the DB entitlement row (mapping_company_feature / useIsFeatureEntitled, now removed); hasMaintenancePortal reads useFeatureFlag('maintenance-portal') -> LD feature-maintenance-portal (false fallthrough, targeted per organization), like every other company gate in the menu. The Maintenance Portal section is now who-you-are only (requiresTier2: !canSeeMaintenancePortal, no requiresFlag): every T2 seat sees it at every company regardless of flag (no_license is the Free tier as before), a staff seat only with Portal Sales. This is a deliberate widening vs today's prod, where the DB entitlement withheld the section from T2 seats at unentitled companies. Site Data > Maintenance (Program, Compliance, Reports) lists for any seat with features.assets.view (AM, PM, EE, FM, Technician; not a pure Admin), is disabled with one tooltip when the company's LD flag is off, and its URLs sit behind FeatureGate on the same flag and admit on the same rule, so menu and route agree. Caveat: the backend /features/sync LD push (launchdarkly_push_service) is inert in every environment (no LD_API_TOKEN mapped); if it is ever configured, exclude maintenance-portal from that push first - noted in the Layout.jsx comment.

### Fixes

* eg-pz-frontend #1613 - UI Sidebar: Maintenance Portal is Portal Sales only; Site Data > Maintenance rides the company flag (#1584)

Note: #1613 is a cherry-pick -x promotion into cicd/dev of prod hotfix #1584 (Console task #51); the same change is already live on cicd/prod.

### QA Review

Environment: Dev only (cherry-picked to cicd/dev; already live on prod). On dev/qa the LD flag fallthrough is TRUE, so every company evaluates feature-maintenance-portal as true there.

* Sign in as a staff user holding Admin / PM / AM / Facility Manager / Super Admin but WITHOUT Portal Sales -> the Maintenance Portal rail section is gone.
* Assign Portal Sales to that same user and reload -> the Maintenance Portal section returns and the route is reachable.
* Negative case: confirm Super Admin specifically loses the portal when it does not hold Portal Sales.
* As a T2 (portal) seat -> Maintenance Portal shows at every company regardless of the flag.
* With the company's feature-maintenance-portal LD flag OFF -> Site Data > Maintenance (Program, Compliance, Reports) show disabled with a tooltip and the routes are gated by FeatureGate; with it ON -> enabled.
* A seat with features.assets.view (AM/PM/EE/FM/Technician) sees Site Data > Maintenance; a pure Admin does not.

# ZP-4645 — [Task #102] SLD issue severity rework + SKM export acknowledgement gate

Status: Ready for QA · Assignee: Eric Ehlert · Labels: frontend, ui

## Description

### What's the problem

On the SLD, issue severity didn't reflect how badly each problem breaks an SKM / Engineering export, so users couldn't tell blocking errors apart from cosmetic warnings. The Issues widget also carried permanent SKM-info rows that added noise. Worst of all, an Engineering XML could be exported from a model that still had blocking errors without the user ever being warned, producing a broken import downstream.

### What's the solution

Reworked SLD issue severities so each type maps to warning vs error by how much it breaks an SKM import: voltage conflict / missing-phase-config / incompatible phase config / eqplib voltage mismatch become warnings; bus-to-bus (no blocker), blocker-to-blocker, terminator-to-blocker, overcrowded terminal, and SKM-unsupported / uncategorized classes become errors.

Removed the permanent skm.settings_revert and skm.ground_fault_dropped rows from the Issues widget and moved breaker / Red Book detection into computeSkmExportNotices.

Added a new SkmExportAcknowledgeDialog in front of both export paths (the SLD export menu and Assets -> SKM -> Export). It lists error-level issues and requires a topology acknowledgement, and when the model has breakers or 3 AWG Red Book cables it also requires a Settings Verifier acknowledgement with the EG Utils download link and a Learn more section. The pre-export check is reused for the bundle PDF, so there is no double fetch.

Caveat / promotion: src/sld changed, so the SLD viewer OTA must be republished per env (prod + bces-iq for prod).

### QA Review

* Environment: dev only (cicd/dev; not yet promoted to QA).
* Open an SLD with voltage conflicts / missing phase config: those issues should now show as warnings.
* Create a bus-to-bus connection, blocker-to-blocker, terminator-to-blocker, an overcrowded terminal, or add an uncategorized / SKM-unsupported class: those should show as errors.
* Confirm the Issues widget no longer shows permanent 'settings revert' / 'ground fault dropped' info rows.
* From the SLD export menu and from Assets -> SKM -> Export on a model with error-level issues: the SkmExportAcknowledgeDialog appears, lists the error issues, and blocks export until the topology acknowledgement is checked.
* On a model with breakers or 3 AWG Red Book cables: the dialog also requires the Settings Verifier acknowledgement and shows the EG Utils download link; 'Learn more' expands.
* Export the bundle PDF: the pre-export check runs once (no double fetch).
* Negative: a clean model with no error-level issues exports without the acknowledgement gate.
* After merge, republish the SLD viewer OTA per env and verify on the published viewer.

# ZP-4753 — Type-to-search multi-pick on dataset-backed EG form multiselects (Web + iOS)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: frontend, ui

## Description

### What's the problem

Dataset-backed multiselect fields in the EG form renderer showed every option as a plain, unfiltered list. When a dataset backs a multiselect that has many options, field users had to scroll the whole list to find and tick each value — slow and error-prone on both web and iPad. The single-select variant of this was already fixed (ZP-4751); the multiselect controls were still unfiltered.

### What's the solution

Added a type-to-search "multi-pick" affordance to dataset-backed EG form multiselect controls on both platforms: the web renderer (EGFormRendererV2) and the iOS searchable multi-pick sheet. Users can now type to filter the option list and tick multiple matches. Shipped as a prod hotfix and cherry-picked up to dev on both repos (web -x 6a10b8e, iOS -x 8b55954).

### QA Review

Environment: Dev only — web cicd/dev and iOS release/dev. Not yet promoted to QA.

* Open an EG form containing a dataset-backed multiselect field that has many options (test on web and on iPad/iOS).
* Confirm a search box appears in the multiselect control; type a partial string and confirm the option list filters to matching options.
* Tick several filtered options; confirm all selections persist and are saved with the form.
* Negative: clear the search text and confirm the full option list returns while previously-ticked options stay selected.
* Regression: confirm single-select dataset-backed fields (ZP-4751) still filter and select correctly.

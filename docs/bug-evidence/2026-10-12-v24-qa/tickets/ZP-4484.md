# ZP-4484 — SKM XML export: emit GF_* ground-fault library fields on Protection

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend

## Description

### What's the problem

SKM/PTW XML exports dropped ground-fault (GF) data on protective devices. SKM models ground fault as a separate library entry ('Low Voltage Breakers - Ground Fault') that PTW's XML importer cannot attach to the parent breaker, so the Function=Ground settings never landed in the exported study. A breaker that had a paired GF device exported without its ground-fault function and settings, forcing an engineer to re-add the Ground function by hand on the SKM side.

### What's the solution

skm_export_service now emits a GF\_\* library block (GF_FunctionName through GF_Settings, synthetic ids 990001xx matching the EG-format ImpEx export) on any Protection node whose skm_settings.ground_fault names a paired GF library device. Frame/sensor/plug resolve by stored row id first, then fall back to the parent breaker's chassis (paired SST+GF devices share frame structure) using the same fallback chain as the front-end 'gfPicks' configurator. GF emission is best-effort — wrapped in try/except so a resolution failure is logged and never breaks the export — and is deliberately kept out of the standalone device export's \_PROTECTION_FIELD_IDS table so unpaired breakers do not receive empty GF fields.

### QA Review

Environment: Dev only (cicd/dev). This is a cherry-pick (-x) promotion of prod hotfix #1393 to cicd/dev; it is present in the cicd/qa...cicd/dev diff and not yet in QA.

* Export an SKM/PTW XML for a study containing a breaker that has an added ground-fault (an SST+GF device pair).
* Confirm the exported XML now carries the GF\_\* block on that breaker: Function name 'Ground', the correct GF library Type/Description, Frame/Sensor/Plug, and the segment settings string.
* Import that XML into PTW and confirm the Ground function is attached to the parent breaker with the expected settings.
* Negative case: export a breaker with NO ground-fault pair and confirm no GF\_\* fields are emitted (no empty GF block appears).
* Resilience: for a breaker whose GF library device cannot be resolved, confirm a warning is logged and the export still completes as a valid file with the rest of the data intact (GF simply omitted).

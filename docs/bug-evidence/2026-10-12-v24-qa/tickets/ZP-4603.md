# ZP-4603 — Task #88: Distinct SLD symbols for more classes + converter placement in the class picker

Status: Ready for QA · Assignee: Eric Ehlert · Labels: backend, frontend, migration, ui

## Description

### What's the problem

Many equipment classes on the single-line diagram shared a borrowed or generic icon, so the diagram could not tell them apart: Load drew as a motor, 3-Winding Transformer as a 2-winding, four classes as the generic dotted circle, and Series Reactor / PDU / Panelboard / Other shared the panel icon. Capacitor Bank reused the inline Series Capacitor symbol, Relay's 'R in a circle' read like the motor's M, the bus-role disconnect switches (Disconnect / MV / DC Disconnect) drew the bare protective switch, DC Circuit Breaker / DC Fuse drew the AC icons, DC Capacitor drew inline although it is an endpoint, and the DC mark's dashed line read as solid. Lightning Arrester was a pass-through with an unused LOAD terminal although it ends the line, and Instrument Transformer had no secondary output. Separately, the +Asset class picker buried both converters (Rectifier, Inverter) under 'Other Equipment' on the AC tab because they are AC-typed with role 'other', so the inverter - placed from the DC side - was not where anyone looks. The solar/battery class names also carried the DC qualifier on the AC class.

### What's the solution

Three idempotent icon-data migrations (ldicon_a1 -> a2 -> a3, chained on cnote_a1) redraw the symbols and remap classes: distinct icons for Load, 3-Winding Transformer, Shunt/Series Reactor, Lightning Arrester (now a role endpoint with a Protected output), Instrument Transformer (secondary output), Meter, PDU, Panelboard, Other; grounded Capacitor Bank, SKM-style Relay, boxed switches for Disconnect/MV/DC Disconnect; DC marks on DC Circuit Breaker / DC Fuse / DC Disconnect, grounded DC Capacitor, and every DC-mark dash redrawn as three butt-capped dashes. Rows still on a global's old icon are moved; custom icon choices are preserved. Class renames by global key: PV Array -> DC PV Array, AC PV Array -> PV Array, Battery -> DC Battery (ids/keys unchanged); SKM import rules and export fallbacks follow the new names (old names still accepted). On the frontend the ClassPicker gives the converters their own headings: Rectifier -> AC tab 'AC/DC Conversion', Inverter -> DC tab 'DC/AC Conversion' (display only - current_type is untouched so the AC/DC connection rule still works), with en + fr strings.

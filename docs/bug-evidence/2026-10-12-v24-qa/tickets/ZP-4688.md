# ZP-4688 — [Web] TV / DGA work orders: native torque & fluid-sample capture, server-raised issues, maintenance check-off dates

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, backward-compatibility, frontend, migration, schema, ui

## Description

### What's the problem

Torque Verification (TV) and fluid-sample (DGA) work could only be captured through special EG form components, so a record was never tied to the work order's service. The work-order grid showed nothing about torque logs or fluid samples, the web never surfaced when a record raised a finding, and no issue was raised automatically when a connection was left loose or a sample graded out of limits. Separately, iOS had no way to show an asset's maintenance history offline: the site sync bundle said which services were checked off but not when.

### What's the solution

Backend (#1484) adds TV (Clean/Tighten/Torque) and DGA as first-class service types with work-order view defaults. A torque record or fluid sample created with a session_id is stamped with the work order and its service; the server raises the issue itself (torque only when a connection moved and was not brought back to spec, with resolve/reopen on later edits; fluid at Condition 2 or worse), while asset-page records raise only by an explicit POST /torque-records/<id>/issue or /fluid-samples/<id>/issue. The work-order payload carries per-asset record counts and the worst band. For Task #107, every ir_sessions\[\] entry now carries service_check_dates ({node_id:{service_id:UTC}}) so iOS can render maintenance history offline. Frontend (#1673) adds the TV/DGA count pill column (coloured by worst condition) opening the asset drawer, work-order-bound record sections with the server's issue state and a Create-issue affordance for asset-page findings, torque/fluid dialogs, Add-by-AI binding, and TV/DGA as creatable service types. Caveat: the feature ships dormant — \`flask switch-record-services\` retypes the three global services per environment only after that environment's field users have an iOS build with native torque/fluid entry; until then the global services stay PM Forms and keep their forms.

### QA Review

Environment: dev only (not yet in QA).

* On a TV or DGA work order, confirm the grid shows a Torque / Fluid Sample count pill coloured by the worst condition, and that clicking it opens the asset drawer on Torque Records / Fluid Samples.
* Add a torque record from a work order; confirm it is bound to the work order ("This work order") and shows the server-raised issue. Move a fastener off OEM spec -> issue raised; correct it -> issue resolved; loosen again -> issue reopens.
* Add a fluid sample awaiting results; edit to Condition 3 -> confirm a fluid issue is raised (Condition 2 or worse).
* Confirm an asset-page record with a finding and no issue offers "Create issue", and that creating it hits the manual issue endpoint.
* Confirm TV (Torque Verification) and DGA (Fluid Sample Analysis) are creatable service types, and fluid panels list Dissolved Gas first.
* Verify the site-sync bundle now includes service_check_dates per ir_session (negative case: an asset with no check-offs returns an empty map, not an error).
* Negative: a plain (non-TV/DGA) work order shows no torque/fluid column and no auto-raised issues.

### Migration — needs review

Backend #1484 ships migration ctt_a1 (revises ehist_a3, single head): adds service_id / issue_id to torque_records and fluid_sample_results, partial indexes on session_id, and global issue classes Torque Anomaly / Fluid Sample Anomaly plus one override per company. It is idempotent and every value is a bound parameter. Dev already has the DDL (applied by hand, unstamped), so the migration is a no-op there apart from a description rewrite — confirm it applies cleanly on QA/stage/prod where the DDL is absent.

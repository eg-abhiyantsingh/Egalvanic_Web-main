# ZP-4597 — Node groups in the All Nodes SLD view; tenant-gate node-group routes

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, migration, schema, ui

## Description

### What's the problem

Node-group membership lived only on the per-view mapping (mapping_node_sld_view.node_group_id), so the All Nodes view - which has no mapping rows - could not hold groups at all; grouping (G/Shift+G, Add to Group, Remove, assign-to-existing) was disabled there. Separately, none of the node-group routes checked the caller's company or site, and malformed ids returned 500.

### What's the solution

Migration ngall_a1 adds nodes.node_group_id (FK node_groups, ON DELETE SET NULL, partial index) to hold All-Nodes membership on the node row (as All-Nodes positions/collapse already are); Node.to_dict emits it, and view payloads still overwrite it from the mapping so it cannot leak into named views. view_id:'all' writes/reads All-Nodes membership; a named view now lists only its own groups. Assign verifies the group is on the node's SLD and in the same view scope; delete also clears nodes.node_group_id (soft-delete means the FK never fires). Every node-group route is tenant-gated via caller_can_reach_sld (404), and malformed ids return 400. Frontend loads groups for the All Nodes view and removes the 'all' gates so assign/ungroup send view_id:'all'.

# ZP-4557 — Torque Records (task #55): typed torque logs, Torque Verification service, AI torque rules — backend + web + iOS

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, migration, schema, ui

## Description

### What's the problem

Bolted-connection torque checks lived only inside EG-form JSON: there was no per-asset torque history, no trend, no reuse of the equipment's own torque specs, and the field tech typed every factory torque off a nameplate by hand. On the web there was no asset-level home for torque, the torque form rendered as a wide horizontal-scroll table on small screens, and the tech had to leave the form to look up an asset's torque specs.

### What's the solution

Task #55 adds Torque Records as the torque sibling of Fluid Sample Analysis, across backend, web and iOS:

* Typed records: torque_records + torque_record_entries (one per connection) with torque_eligible on node classes and subtypes; server-derived per-connection status (tight / re-torqued / loose / not verified) and a record roll-up.
* A record_sink:"torque" projector (FSA lifecycle): a submitted form writes one record per asset, the record follows the instance, delete retracts; carry-forward ghosts for the connection list; flask rebuild-torque-records.
* A global Torque Verification service; Clean / Tighten / Torque repointed to their own copy of the form (flask seed-torque-services, idempotent).
* AI torque rules on the asset: nameplate extraction fills a new hidden reserved core attribute (Torque values), and an after-commit, fingerprint-gated post-processor turns that text + the amp rating into rules; conductor sizing (NEC 310.16 / 250.122) is deterministic code. Manual editor via GET/PUT /node/<id>/torque-rules (renames keep ids; AI never overwrites a user rule) + refresh.
* Field-friendly EG form: log Type is a select over the linked asset's rules (in-memory torque_rules source) with option_fills (unit + factory torque); new generic EG-form options (card layout at phone width, inherit, disabled_if, default_today, users source, option_fills, default_single_option, hide_without_options) documented in agent/docs/eg_form_schema.md.
* Web Torque Records tab on asset detail: summary cards, inspection logs, connection-history heatmap, torque-rules editor, Extract from Photos, manual record dialog and Add by AI (historical log import); Torque Log block in the form builder; hidden core attributes skipped in every web attribute view/editor/grid/filter.
* iOS: offline torque logs, asset torque rules and the field-friendly torque form.

Caveat: from the moment migration tq_a3 runs until the iOS build carrying #664 (and the SLD viewer OTA bundle) ship, iOS renders the hidden "Torque values" attribute as an ordinary textarea on torque-eligible classes. Nothing gates on it and edits are silently kept at the stored value, so it is cosmetic — ship the iOS build close to the backend promotion. Migrations tq_a1 → tq_a2 → tq_a3 (parented on swjrnl_a7, single head). After deploy per env: flask seed-torque-services, then optionally flask refresh-torque-rules once extractions exist.

### QA Review

Environment: dev only (not yet in QA).

* Mark a node class / subtype torque_eligible in the class editor; confirm a Torque Records tab appears on its assets and is absent on ineligible assets.
* Submit a Torque Verification (Clean / Tighten / Torque) form; confirm one torque record is written per asset, per-connection status and roll-up compute, and deleting the instance retracts the record.
* Run nameplate extraction on an asset with torque data; confirm torque rules populate; edit rules in the manual editor (rename keeps ids; a user rule is not overwritten by a later AI read); exercise GET/PUT /node/<id>/torque-rules and POST .../torque-rules/refresh.
* In the torque form, confirm log Type is a select over the asset's rules with unit + factory torque auto-filled; confirm the card layout at phone width has no horizontal scroll.
* Add by AI: import a historical torque log file; confirm add-only rows and that the source file is kept as an asset attachment.
* Deploy: run flask seed-torque-services; verify the hidden "Torque values" attribute never renders / exports / column-matches on web.
* Negative cases: tenant 404s and validation 400s on the per-asset API; form-sourced rows are locked (409).
* After deploy, ship the iOS build (#664) close to the backend promotion so the hidden attribute is not shown as a plain textarea on iOS.

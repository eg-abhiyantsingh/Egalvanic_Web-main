# ZP-4613 — Ship ultrasonic scans in the full-SLD sync payload for offline UT work orders (Task #93)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, schema

## Description

### What's the problem

iOS pulls everything it needs for offline work from GET /sld/v2/<id>, but ultrasonic scans (task #79) were only exposed through their own /ultrasonic-scans endpoints. A UT work order therefore showed no scans on a phone that went offline without first opening the scan screens.

### What's the solution

get_sld_full_v2 now includes an ultrasonic_scans field - every scan on the SLD's nodes, soft-deleted ones included (so devices learn about deletions), each carrying presigned image_url / audio_url (1 h, signed locally with no S3 round trip) for the files that exist. Same shape as the /ultrasonic-scans routes (UltrasonicScan.to_dict() plus URLs), mirroring the existing torque_records / fluid_sample_results helpers. No migration.

### Fixes

* eg-pz-backend #1456 - Task #93: ship ultrasonic scans in the full-SLD sync payload

### QA Review

Environment: dev only.

* On dev, call GET /sld/v2/<id> for an SLD whose nodes have ultrasonic scans; confirm the response includes ultrasonic_scans with each scan's fields and presigned image_url / audio_url only for files that exist.
* Soft-delete a scan and confirm it still appears in the payload so clients can reconcile the deletion.
* Confirm the paired iOS build shows UT scans offline after a single SLD sync.
* Negative: a node with no scans returns an empty list, not an error.

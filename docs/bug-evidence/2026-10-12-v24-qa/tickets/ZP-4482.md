# ZP-4482 — Engineering XML export ships as a zip bundle with READ THIS BEFORE IMPORTING.pdf

Status: Ready for QA · Assignee: Eric Ehlert · Labels: frontend, ui

## Description

### What's the problem

Everything an engineer needs to know about an export - standing SLD issues, exporter messages, classes exported as generic loads, settings SKM will reset - lived only on the SLD issue list and in a toast. Neither travels with the file, so whoever runs SKM later, often on another machine, has no record of the model's caveats.

### What's the solution

Export Engineering XML now downloads one zip from both entry points (the SLD export menu and Assets > SKM), containing the byte-for-byte XML (skm_export\_\*.xml), a 'READ THIS BEFORE IMPORTING.pdf' (every SLD issue standing at export, exporter messages, classes exported as generic loads, Settings Verifier steps and a file list), and one CSV per worklist issue. Issues are computed from a fresh full-graph fetch, so the summary describes the saved state the backend exported; a view export narrows issues/counts/CSV rows to the assets in the view. Graceful degradation: if the issue check cannot run the XML still ships and the PDF says so; if the bundle cannot be built at all the bare XML downloads and the UI says so. The 'SKM will reset trip settings' notice now links to the Settings Verifier for any model with a circuit breaker (plain text in the embedded iOS viewer). No new dependency (the zip is written by the store-only src/utils/zipStore.js; jsPDF is loaded via dynamic import to stay out of the initial chunk) and no backend change. Caveat: files under src/sld/ changed, so iOS needs the SLD viewer OTA bundle republished per environment. Landed as prod hotfix #1570 cherry-picked to cicd/dev.

### QA Review

* Environment: dev only (cicd/dev; cherry-pick of prod hotfix #1570, not in cicd/qa).
* From both the SLD export menu and Assets > SKM, run Export Engineering XML and confirm a single zip downloads containing skm_export\_\*.xml, READ THIS BEFORE IMPORTING.pdf, and one CSV per worklist issue.
* Confirm the PDF lists standing SLD issues, exporter messages, classes exported as generic loads, Settings Verifier steps and the file list; confirm the XML is byte-identical to the previous bare export.
* Confirm a view-scoped export narrows issues/counts/CSV rows to the assets in the view.
* Confirm the 'SKM will reset trip settings' notice appears for any model with a circuit breaker and links to the Settings Verifier dialog.
* Negative: force the issue check to fail and confirm the XML still ships with a PDF noting the check did not run; force a bundle build failure and confirm the bare XML downloads with a UI message.

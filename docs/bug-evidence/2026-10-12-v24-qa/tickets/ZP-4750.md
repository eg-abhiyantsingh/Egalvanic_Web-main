# ZP-4750 — SKM export: option to omit the building from arc-flash label numbers

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, ui

## Description

### What's the problem

When exporting an SKM arc-flash study, the generated label numbers always carried the building identifier as part of the label. Customers whose labeling conventions don't include the building had no way to drop it, so labels came out longer than needed and inconsistent with how those sites physically tag equipment. This followed on from the earlier change that lets label numbers be generated from the bus location (ZP-4746), which exposed the building segment in the first place.

### What's the solution

Added an opt-in option in the SKM export flow to omit the building from the arc-flash label numbers. The backend SKM XML output now formats label numbers without the building segment when the option is set; the frontend surfaces the toggle in the SKM export dialog (new label-numbers option control) and passes the choice through the export service. The default preserves existing behavior, so labels keep the building unless the user turns the option on. This shipped as a prod hotfix (Task #145) and was cherry-picked down to cicd/dev.

### QA Review

* Environment: dev only (cicd/dev; the feature is also live in prod as the source hotfix, but not in cicd/qa).
* Open the SKM export dialog for an asset/SLD that produces arc-flash labels and confirm the new option to omit the building appears alongside the existing label-number-from-location option.
* With the option OFF, export and confirm label numbers still include the building segment exactly as before (default/back-compatible path).
* With the option ON, export and confirm the generated label numbers omit the building while remaining unique and correctly ordered by bus location.
* Negative case: verify toggling the option does not affect non-arc-flash exports and that the setting round-trips in the export dialog (acknowledge dialog included).

# ZP-4621 — Task #100: Batch node position moves and All-Nodes collapse apply as one queued mutation

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, migration, schema

## Description

### What's the problem

iOS multi-node moves (magic layout, straighten, area move) replayed on the web editor one node at a time: around 12 separate queued mutations roughly 120 ms apart, each its own commit and realtime broadcast, making multi-node layout slow and noisy. The per-node position path also loaded nodes by client-supplied ids with no company scoping, so a caller could move nodes outside their own tenant. Separately, the batch_positions and batch_collapse mutation ops were missing from the mutation_op Postgres enum, so iOS's PUT /node/batch-positions returned 500 (invalid input value for enum mutation_op) and silently fell back to per-node writes.

### What's the solution

New PUT /node/batch-positions applies as a single queued mutation (node/batch_positions): entity id = sld_id or the first node, lane = the SLD, worker handler maps 400/403 to permanent and everything else to transient. NodeController.batch_update_positions now adds a tenant check (every node must belong to the caller's company, fail closed) and input bounds (list <= 2000, node_id must be a UUID, x/y required, x/y/width/height finite with |v| <= 1e6, booleans rejected); the web route passes strict_company_id(). SQS terminal receipts are now deleted with one delete_message_batch per receive (one-by-one fallback). Migration mqop_a1 (revises ehist_a2, single head) adds batch_positions and batch_collapse to the mutation_op enum via ALTER TYPE ... ADD VALUE IF NOT EXISTS in an autocommit block, and a guard test asserts every MUTATION_ROUTES op exists in the base enum or a migration's NEW_OP_VALUES.

### Fixes

* eg-pz-backend #1462 - Task #100: /node/batch-positions as one queued mutation; tenant-scoped + bounded; batched SQS deletes
* eg-pz-backend #1463 - Task #100: add batch_positions + batch_collapse to the mutation_op enum

### QA Review

Environment: dev only (not yet in QA).

* On dev, perform an iOS multi-node move (magic layout / straighten / area move) and confirm it replays on web as a single batched update (one commit, one realtime broadcast) rather than \~12 serial per-node moves.
* Confirm PUT /node/batch-positions no longer returns 500 'invalid input value for enum mutation_op'; the batch applies and no per-node fallback occurs.
* Tenant / fail-closed: a batch referencing a node outside the caller's company is rejected (403) with no partial writes.
* Bounds: reject a batch of more than 2000 nodes, a non-UUID node_id, missing or non-finite x/y, and boolean coordinate values.
* Confirm the All-Nodes collapse cascade (batch_collapse) applies without the enum error.

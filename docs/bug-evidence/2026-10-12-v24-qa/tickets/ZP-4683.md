# ZP-4683 — [Web] Work order + asset batch: service-driven record sections, scope by parent asset, SLD focus, UT for all classes, NA-safe bulk import

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, schema, ui

## Description

### What's the problem

Which maintenance-record sections an asset showed (Fluid Samples, Torque Records, Ultrasonic) was driven by fsa_eligible / torque_eligible flags duplicated on node classes and subtypes - a second copy of what the service catalog already said, and it had drifted: a Clean/Tighten/Torque service wrote torque records on fuses, relays and MV cables that the flags hid, and Torque Verification was missing DC/solar classes. On the web, Ultrasonic only appeared once a scan existed.

Separately, building a work order's scope offered no way to say 'this enclosure and everything inside it' (no parent-asset filter), and the scope dialog spent its height on a stepper, a service picker and an outer scrollbar. There was no way to open the SLD focused on one asset - Open in SLD zoomed to a fixed level, so an enclosure overflowed and a cable could not be shown. And bulk import silently dropped a whole location when a room or asset was literally named 'NA' / 'N/A' / 'NULL' / 'None', because pandas read those as blank.

### What's the solution

Record-section visibility now follows the service catalog on both server and device. New record_section_eligibility: a section shows when a service feeding that record type evaluates to the asset (work-order rule walk, first match wins, empty method list = out of scope) or the asset already has records. New GET /node/<id>/record-sections returns {sections:{fsa,torque,ut}} for the web asset page, tenant-scoped. Rules-bundle methods now carry record_sinks so the device answers the same question offline. Ultrasonic Testing is seeded to every non-bus global class (cables excluded) via flask seed-ultrasonic-service.

Web: the asset picker gains a Parent-asset filter; while a service's scope is edited the stepper collapses and the service select + Save move into the header with no outer scroll; window.focusNode(id) / focusNodeId focus the SLD at the largest zoom where the asset plus a margin fits (capped at reading zoom, with cables / hopped-over bus nodes resolved to their drawn link); the Fluid Samples / Torque Records / Ultrasonic tabs now read the new endpoint, and the class-editor flag controls and the 'records will be hidden' warnings are removed (a stored record always shows). Bulk import keeps a literal 'NA'/'N/A'/'NULL'/'None' in name columns (every other column reads as before) and warns on a partial location.

Caveat: fsa_eligible / torque_eligible are no longer read or accepted but are intentionally kept serialized and frozen for app builds from before this change; drop the columns in a later release. No migrations. Post-deploy seeds are required per environment: flask seed-ultrasonic-service and flask seed-torque-services (already applied on dev by hand). The SLD viewer file ships in the iOS OTA bundle - republish with scripts/publish-sld-viewer.sh per environment.

* From an asset, use Open in SLD and confirm it focuses that asset at a zoom where the asset + margin fits (enclosure no longer overflows); confirm a cable / hopped-over bus node is located via its drawn link.
* Bulk-import a sheet with a Room literally named 'NA' (also 'N/A', 'NULL', 'None') and confirm the location is kept, not dropped; confirm a partial location raises a validation warning; confirm non-name columns still read NA as blank.
* Negative: an asset with no applicable service and no records shows none of the three record tabs.

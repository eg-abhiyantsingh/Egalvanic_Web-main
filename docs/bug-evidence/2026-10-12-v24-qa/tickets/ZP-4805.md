# ZP-4805 — SKM export: group eg_y at the bus-bar midline, not the top-left (task #165)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: backend

## Description

### What's the problem

In the SKM XML export, panel/enclosure groups landed in the wrong vertical place, so lineside children drew visually below their parent group instead of hanging off its bus bar (task #165).

Root cause: a group's exported eg_y used the group's top-left y. On the SLD drawing only the group's bus bar is visible (the left-edge midpoint of the box), not the whole enclosure, so a top-left y shifted the whole group up relative to where the editor actually shows the bar. A secondary gap: view-scoped exports took width/height straight from the view mapping, which can be null, instead of falling back to the node's own dimensions the way the SLD editor does.

### What's the solution

A non-simplified group's exported eg_y is now its bus-bar midline (top + render-height/2), matching where GoJSGraphEditor's group template draws the bar; children still resolve against the group's top-left. Simplified groups (drawn as a plain symbol with no bar) keep the top-left.

Render height mirrors the SLD editor's enclosure floor (ENCLOSURE_MIN_WIDTH 170 / ENCLOSURE_MIN_HEIGHT 90 from src/sld/src/App.jsx): a missing height floors to 90, and a legacy-small box (both axes under the floor) is clamped up to 90; a wide-but-short box is honored as stored. \_pos now also carries height and is_simplified, and view width/height fall back to the node's own values when null.

Caveat: the export now duplicates frontend layout constants (ENCLOSURE_MIN_WIDTH/HEIGHT and the bar-at-half-height rule). These must be kept in step with the SLD editor (App.jsx, GoJSGraphEditor group template, nodeUtils.js) or the export and the on-screen drawing will drift apart again.

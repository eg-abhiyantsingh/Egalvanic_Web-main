# ZP-4514 — Cable drop inserts node buses on its own two halves only, never re-running rules over the whole component

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend

## Description

### What's the problem

On the web canvas, dropping a cable / pseudo-edge (POST /edge/insert-pseudo-edge) ran apply_rules over the whole connected component, which could split an edge the user had drawn earlier. Repro on dev (9/30): connect MC -> Motor Overload directly (inserts nothing), then connect Motor Overload -> Disconnect Switch with a Cable. Step 2 wrongly produced two node buses - the correct one on the new Motor Overload -> cable half, and an extra one on the pre-existing MC -> Motor Overload edge - because apply_rules judged the whole bus-to-bus chain from one snapshot and its seam choice ('before the 2nd blocker') flipped with a walk direction that follows unordered Node query rows.

### What's the solution

insert_pseudo_edge no longer calls apply_rules. A new helper, sld_rules.pseudo_edge_bus_plan, decides whether each of the two new halves needs a bus - a Python port of the canvas's pseudoEdgeInsertionPlan / halfNeedsBus (connectionRules.js), so web now matches iOS. It never touches any other edge. The response shape is unchanged, so there is no FE or OTA change and repositioning / view mapping behave as before. Left on apply_rules: /edge/create (its pair check is already local), resolve-impedance-insertion, and bulk upload / bulk edit.

### Fixes

* eg-pz-backend #1404 - Cable drop inserts Node Buses on its own two halves only

### QA Review

Environment: dev only.

* Reproduce: connect MC -> Motor Overload directly (no bus inserted), then connect Motor Overload -> Disconnect Switch with a Cable; confirm a bus is added only on the new (line-side) half and the pre-existing MC -> Motor Overload edge is untouched (no second bus).
* Confirm normal cable drops still insert buses where the two halves require them.
* Confirm the other flows (/edge/create, resolve-impedance-insertion, bulk upload/edit) behave as before.
* Negative: dropping a cable no longer rewrites or splits any unrelated edge in the component.

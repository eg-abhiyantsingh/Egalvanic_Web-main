# ZP-4559 — Work-order list: full-access roles (PM/EE) win over Account Manager scoping

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend

## Description

### What's the problem

On prod, a user holding Account Manager together with Project Manager or Electrical Engineer got an empty (or account-only) work-order list on the web (POST /company/<id>/workorders/v2, GET /company/<id>/sessions). apply_session_access_scope checked the Account Manager branch before FULL_SESSION_ACCESS_ROLES, so a PM/EE with no account links fell into filter(False) — even though roles are treated as a union everywhere else and iOS (/sld/v3 → can_see_all_sessions) already showed these work orders. It surfaced when the Foundation customers' Super Admin role (which returned early via ADMIN_ROLES) was replaced with PM + AM + EE: 46 users affected, 22 seeing no work orders at all (e.g. Hi-Tech's rparsons at Arvco Cadillac).

### What's the solution

apply_session_access_scope now returns unrestricted for ADMIN_ROLES | FULL_SESSION_ACCESS_ROLES before the Account Manager branch; Account-Manager-only users keep the account scope, other roles keep "assigned only". get_company_sessions (and session_routes.py) use the shared helper instead of an inline copy that carried the same ordering bug. 11 regression cases were added, including the PM + AM + EE-with-no-accounts case. Shipped first as a prod hotfix (#1417) and cherry-picked clean (-x) to cicd/dev as #1420; qa/stag cherry-picks still pending.

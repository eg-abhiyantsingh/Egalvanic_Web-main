# ZP-4512 — Journal fold Lambda: read web-uploaded photos whose S3 URL carries a presigned query string, and grant the ai_usage archive

Status: Ready for QA · Assignee: Eric Ehlert · Labels: 

## Description

### What's the problem

The web stores a journal photo's row with the full presigned upload URL (the .jpg object followed by an X-Amz-Algorithm query string). The journal fold Lambda's \_split_url kept the query string in the S3 object key, so every web-uploaded photo logged 'not readable from eg-pz-<env>-s3-asset-photos-ohio' and the model never saw it - on demo.dev walk 7554a35f the generator fold called look_at_photos and got 0 photos, so its proposal carried no photo claim. Separately, the Lambda role could not write the ai_usage archive (AccessDenied on PutObject; non-fatal), leaving journal folds as the one flow left unarchived.

### What's the solution

\_split_url now drops the query string and fragment before unquoting the key (tests added for a presigned URL and for a URL with no key). infra/bootstrap_journal_fold.sh grants the Lambda role read/write on eg-pz-<env>-s3-ai-usage-ohio like the other flows' Lambdas; dev's role was granted by hand the same day (write-ai-usage-dev) and qa/staging/prod get it from the bootstrap. Note: a matching \_split_url fix for the backend Step Function staging path (the envs still on the old runner) follows separately.

### Fixes

* eg-pz-engineering-ai-pipeline #134 - Journal fold Lambda: read photos whose stored URL carries a presigned query; archive usage

### QA Review

Environment: dev only.

* Upload a photo to a journal entry from the web and run the fold: confirm the photo is read (no 'not readable from ...-s3-asset-photos-ohio' log) and the model's proposal carries the photo claim.
* Confirm the fold's ai_usage is archived to eg-pz-dev-s3-ai-usage-ohio with no AccessDenied on PutObject.
* Negative: a photo row whose URL has no object key still folds without error.

# ZP-4574 — Merge Alembic heads tqlock_a1 + swjrnl_a8 to unblock cicd/dev migrations

Status: Ready for QA · Assignee: Eric Ehlert · Labels: backend, migration

## Description

### What's the problem

Two backend PRs that merged to cicd/dev 21 seconds apart -- #1421 (tqlock_a1, lock record-sink keys) and #1414 (swjrnl_a8, site-walk release) -- both revised the same Alembic revision tq_a3, leaving two migration heads. The #1414 dev deploy failed at Run Database Migrations with 'Multiple head revisions', and every later backend push to cicd/dev would have failed the same way until the heads were reconciled.

### What's the solution

A no-op Alembic merge revision mrg_tqlock_swjrnl whose down_revision points at both heads, collapsing them back to a single head. A single head was verified with ScriptDirectory.get_heads(). No schema change -- the merge revision only reconciles the migration DAG.

### Fixes

* eg-pz-backend #1424 -- Merge alembic heads tqlock_a1 + swjrnl_a8

### QA Review

Environment: Dev only (cicd/dev; not yet in QA).

* Confirm the cicd/dev database migration step runs cleanly (no 'Multiple head revisions') on the next backend deploy.
* Run alembic heads (or ScriptDirectory.get_heads()) against cicd/dev and confirm exactly one head.
* Confirm the merge revision is a no-op: upgrading applies no schema change beyond recording the merge, and both tqlock and swjrnl migrations remain applied.

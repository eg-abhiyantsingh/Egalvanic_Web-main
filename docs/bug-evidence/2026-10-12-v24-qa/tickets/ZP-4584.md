# ZP-4584 — Track per-environment infra bootstrap (schedule-notices, close-stale) with Success-console run markers

Status: Ready for QA · Assignee: Eric Ehlert · Labels: backend

## Description

### What's the problem

The EventBridge schedules for scheduling notices and close-stale were set up by hand in dev and lived in the untracked admin-scripts/ folder. Nothing recorded whether qa, staging or prod had received the same setup at promotion, so the team kept missing it.

### What's the solution

Move the bootstrap scripts into a tracked infra/ folder and record what is armed per environment.

* infra/bootstrap_schedule_notices.sh and infra/bootstrap_close_stale.sh moved from admin-scripts. --enable writes an SSM marker, --disable removes it, so a check in the Success console means 'armed in that env'.
* infra/lib/bootstrap_marker.sh (the same helper the pipeline repo uses) writes /eg-pz/bootstrap/be/<script>/<env> to SSM with commit, time, principal and host.
* infra/README.md documents how per-env infra is tracked via Success console tasks.
* Scripts only; no application code. Markers were written for what is armed today: notices on dev, close-stale on dev + qa.

### Fixes

* eg-pz-backend #1432 - Infra bootstrap scripts with Success-console run markers

### QA Review

Environment: dev only. Scripts/infra only - no in-product behavior to exercise.

* Run infra/bootstrap_schedule_notices.sh --enable; confirm /eg-pz/bootstrap/be/bootstrap_schedule_notices/dev is written to SSM with commit, time, principal and host.
* Run with --disable; confirm the marker is removed.
* Confirm the Success console shows a check for each env where a script is armed (notices: dev; close-stale: dev + qa).
* Review infra/README.md for the documented task.py add-script usage.

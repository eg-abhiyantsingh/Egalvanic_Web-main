# ZP-4586 — Ultrasonic Testing: per-asset scans, UT service type, and global UT report (Task #79)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, migration, schema, ui

## Description

### What's the problem

Newkirk (TKT-1433) performs ultrasonic (Ultraprobe) inspections on assets that cannot be infrared-scanned, but ProZone had nowhere to store an ultrasonic spectrum capture per asset. To get baseline captures into reports, technicians were filing each one as a fake "Ultrasonic Baseline Waveform" issue, which polluted the issue list and left no structured record of frequency, sensitivity, dB, or result.

There was also no Ultrasonic Testing (UT) service type, so UT work could not be scheduled, tracked, or reported as its own discipline.

### What's the solution

Added a first-class Ultrasonic Testing capability end to end. The backend introduces an ultrasonic_scans table (migration ultra_a1, on top of guest_a1) storing the spectrum image (BMP auto-converted to PNG on upload), an optional WAV, frequency/sensitivity/dB, a result (normal / corona / tracking / arcing / mechanical / other), notes, and an issue link; files land in the IR photos bucket under ultrasonic/<session>/<scan>/ with a fresh key per upload.

New routes list/create scans on a work order, edit or soft-delete a scan, and expose an asset's scan history. Every write is tenancy-gated: session routes check caller_can_reach_session (404 on failure), writes re-check company_id, the asset must belong to the work order, the service must be a UT service on that asset, and file keys must sit under the scan's own prefix. A non-normal result raises a single Ultrasonic Anomaly issue using the company's class.

A new UT service type uses data mask ut with completion driven by the per-service checkbox only; /assets/v2 gains ut_scan_count and ut_scan_complete to drive a display-only badge. On the frontend, UT work orders get an Ultrasonic cell (checkbox plus a grey-0 / amber / green badge), an UltrasonicScanSection for capturing and editing scans, a read-only Ultrasonic history tab on the asset page, and an "Ultrasonic (UT)" option in Create Service.

Caveat: flask seed-ultrasonic-service must be run once per environment after the migration, or the global "Ultrasonic Testing" service and its "Ultrasonic Testing Report" config will be missing.

### QA Review

Environment: Dev only (not yet promoted to QA).

* After deploy, confirm migration ultra_a1 applied and flask seed-ultrasonic-service was run; verify the global "Ultrasonic Testing" service and "Ultrasonic Testing Report" config exist.
* Create a work order with the Ultrasonic (UT) service type; confirm the Ultrasonic cell appears with a grey 0 badge and the Tasks tab is hidden.
* Open the cell to the asset drawer Ultrasonic section; upload a spectrum image (test BMP and PNG/JPG) and confirm it previews as PNG; add an optional WAV, enter frequency/sensitivity/dB, pick a result, add notes, and save; confirm the grid refetches and the badge turns amber (image or WAV missing) then green (both present).
* Enter a non-normal result and confirm exactly one Ultrasonic Anomaly issue is raised using the company's class.
* Edit a scan, then delete one (delete confirms in a dialog) and confirm the soft-delete removes it from the list.
* On the asset page, confirm the read-only Ultrasonic history tab appears once the asset has at least one scan.
* Negative cases: an upload over the caps (20 MB image / 50 MB audio) is rejected; a user who cannot reach the session gets 404; a scan against a non-UT service or an asset not in the work order is refused.

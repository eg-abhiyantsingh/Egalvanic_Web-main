# ZP-4618 — Task #97 (R&D): Realtime SLD collaboration - presence + live change broadcast on the web editor

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, migration, schema, ui

## Description

### What's the problem

The web GoJS single-line-diagram editor had no realtime collaboration. Multiple engineers editing the same SLD could not see each other's cursors, selections or live drags, had no presence/who-is-here awareness, and only picked up another person's committed changes after a manual page refresh.

### What's the solution

R&D, dev only, gated behind the sld-realtime flag and REALTIME_NOTIFY - expected to be torn down. Backend adds a standalone FastAPI/uvicorn realtime server (its own ECS service) that LISTENs on a pg_notify('sld_changes') channel emitted by the entity_history flush (delivered on commit, in commit order, dropped on rollback; REALTIME_NOTIFY=0 disables). WebSocket clients authenticate with a 60s HMAC ticket from POST /realtime/ticket (require_auth + slds.view + reachability check). The server reads the notified entity_changes id range, dedupes, and broadcasts committed changes plus presence (cursors / selection / live drag) to the SLD room with size and rate caps. infra/bootstrap_realtime_service.sh provisions the TD/TG/ALB rule/ECS service and --disable removes it.

The web editor renders SldRealtimeLayer when sld-realtime is on (not flowOnly / portal): peer cursors, named selection outlines, live drag, who-is-here avatars, and activity toasts; committed node geometry applies in place (undo manager skipped) and other committed changes trigger a debounced refetch. Own-tab echoes are skipped via an X-RT-Client header. A follow-up (be#1461) narrowed the ALB rule to /api/realtime/ws + /health so /api/realtime/ticket still routes to the API instead of 404-ing to the CloudFront index.

Dev follow-ups (both dev only, same flag): remote-driven model swaps now refresh silently with no loading overlay and restore the prior selection, and the realtime layer defers its refresh while a gesture, dialog, menu or popover is open - so layout ops such as Straighten Downstream no longer find an empty selection when a remote change lands mid-prompt (fe#1644). The realtime activity indicator was moved to a single inline update at the end of the bottom-left toolbar row (replacing the stacked toasts), the bottom row was realigned with the right toolbar, and the canvas-note author byline now renders inside the note instead of hanging under it (fe#1646).

A further dev follow-up (fe#1647, same flag): a group moved remotely now carries its child nodes live - place() uses Group.move(pt, true) to move members recursively for committed moves, live drags and drag reverts (and \_syncProcessedDataForMovedKeys picks up the members), instead of only the parent moving until a refresh.

A further dev batch (all dev only, same flag) completes the realtime feed and extends it to the iOS viewer: the change feed now also tracks view/class mappings, terminals, SLDView/SLDLink/NodeGroup rows (migration ehist_a3, single head) and converts the remaining raw-SQL mutations to ORM so they emit history + NOTIFY (be#1466); POST /sld/<id>/entities returns just the changed nodes/edges of a site in /sld/v2 shape for incremental pulls (be#1465); the realtime layer runs in the iOS app's bundled viewer when the realtime + online flags are set, applying geometry live then asking native to re-fetch only the changed entities via realtimeChanges {node_ids, edge_ids} instead of a full-site pull (fe#1649, fe#1650); and who-is-here presence (live dot + avatars) renders into the web page-header actions slot, with the iOS viewer showing cursors / selection outlines only (fe#1650).

Completion (fe#1651, Phase 3): the web editor's realtime apply engine now applies a remote change exactly like a fresh load - POST /sld/<id>/entities in canvas shape patches the live processed data in place (replace/insert by id, drop gone ids) with no loading overlay and the selection + viewport kept, in All Nodes and inside a view; it defers while a tool/dialog/menu is active, batches, keeps one request in flight, and protects this tab's in-flight edits for 8s or until its own save echoes back (origin = this tab). Two supporting entity-endpoint fixes: include=sld now returns the layout lock (layout_owner_user_id / layout_owner_name) so a realtime lock change updates the banner and drag gate (be#1467), and the entities endpoint no longer counts view-graph reference nodes as present, so a node removed from a view reads as gone on other canvases instead of staying drawn until a refresh (be#1468).

A further dev batch (be#1469, fe#1652, same flag) extends the realtime apply engine to the iPad / iOS-native path. POST /sld/<id>/entities gains include options (touching, mappings, notes, sld) so the native app can refresh just the named entities instead of the whole site; in flowOnly the web apply engine now fetches through the app (realtimeFetch / realtimeNotes) rather than the API - the app upserts SwiftData and answers in the push's own shape, so the engine patches and rebuilds exactly as on web, keeping selection and viewport. An app without the handler never answers and the engine falls back to realtimeRefresh after 15 s. The iOS native side is eg-pz-mobile-iOS #686 (still open).

### QA Review

* Environment: dev only (R&D), behind the sld-realtime flag + the realtime ECS service; expected to be torn down.
* Open the same SLD in the web editor as two different users; confirm each sees the other's cursor, selection outline, live drag, who-is-here avatars and an activity toast on a move.
* As one user commit a node move; confirm it applies in place for the other user with no manual refresh. Commit a non-geometry change and confirm the other editor refetches.
* Negative: a forged or expired realtime ticket is rejected.
* Confirm REALTIME_NOTIFY=0 (or the sld-realtime flag off) disables the layer with no editor regression.
* Confirm /api/realtime/ticket returns JSON (not the CloudFront index.html) - the narrowed ALB rule from be#1461.
* Follow-ups (fe#1644/#1646): trigger a large remote change while a layout op's include-children prompt is open - confirm the selection survives and the op still runs (not moved.size 0); confirm the realtime activity shows one inline update at the end of the bottom row and the note author byline renders inside the note.
* Move a parent/group node on another device or tab and confirm its child nodes move live with it (not just the parent), including during live drag and on drag-revert, without a manual refresh.
* Dev only: with sld-realtime on, open the same SLD in the web editor in two sessions and confirm the page-header actions slot shows a live dot + who-is-here avatars; closing one session removes its avatar within a few seconds.
* Dev only: POST /sld/<id>/entities with a small {node_ids, edge_ids} set returns only those nodes/edges (deleted rows included) in /sld/v2 shape; >500 ids per list or a non-UUID id returns 400; a caller without slds.view or without reach to the path's site is rejected and rows are scoped to that site.
* Dev only (iOS bundled viewer): with feature-sld-realtime on and online, make a change on web and confirm the iOS viewer applies the geometry live and then refetches ONLY the changed entities (realtimeChanges), not a full-site pull; toggling the device offline closes the socket and nothing reconnects; the iOS viewer shows cursors/selection outlines but no avatars/toasts.
* Dev only: edit a view/class mapping, terminal, node group, SLDView or SLDLink and confirm the change reaches the realtime feed / entity history with sld_view_id + ref_type/ref_id set; confirm the ehist_a3 migration applies cleanly as a single head.
* Dev only (apply engine, fe#1651): with sld-realtime on, open the same SLD in two web sessions; make a remote change and confirm the other tab applies it in place like a fresh load - no loading overlay, selection and viewport preserved - in both All Nodes and inside a view; while a tool/dialog/menu is open the apply defers until it closes; the acting tab does not re-apply its own echoed save.
* Dev only (be#1467): POST /sld/<id>/entities with include=\["sld"\] returns sld.layout_owner_user_id / layout_owner_name; take the layout lock as another user and confirm the banner + drag gate update without a full refresh.
* Dev only (be#1468): in a two-tab view harness, remove a node from a view and confirm it disappears from the other canvases (reference nodes excluded, the node reads as gone), matching a fresh load.
* Dev only (be#1469): POST /sld/<id>/entities with include=\["touching","mappings","notes","sld"\] returns incident edges, cross-view node/edge mappings, canvas notes with author names, and the layout-lock owner, under the same tenant gate as the base route.
* Dev only (iPad realtime, fe#1652): with sld-realtime on in the iPad/iOS native viewer, make a change on web and confirm the native app refreshes only the named entities in place (selection + viewport kept); on an app build without the handler, confirm the engine falls back to a full realtimeRefresh after \~15 s.

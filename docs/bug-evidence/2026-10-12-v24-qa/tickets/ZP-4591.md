# ZP-4591 — UI Task #81: Show new connections on unwired terminals immediately; re-block bus-to-bus direct connections

Status: Ready for QA · Assignee: Eric Ehlert · Labels: frontend, ui

## Description

### What's the problem

On the SLD editor (web, and the iOS SLD webview), connecting to a terminal that had no edges yet drew the edge onto the node body, with no terminal dot, until the view was refreshed. The terminal port template hides unwired terminals (connected === false, computed once at load), and a node only carries node_terminals for terminals it has actually used, so GoJS could not attach a link to a hidden or missing port and fell back to the node body.

Separately, "Connect directly" could leave a bus-to-bus chain with no impedance between two buses — a regression introduced by the earlier ZP-3227 frontend change.

### What's the solution

A new ensureTerminalPort() runs inside the link-create transaction: it reveals the target port, or materializes it from the class orientation blueprint when the port does not exist yet. It is wired into createDirectEdge (covering all connection-mode and pseudo-edge paths on web and iOS), the parent↔child edge path, and the iOS window.createEdge / window.createEdgeWithTerminals bridges. Edge payloads are unchanged — the backend still resolves terminals by handle.

"Connect directly" is re-disabled when it would leave a bus-to-bus chain with no impedance, reversing the ZP-3227 frontend change; it reads the backend preview flag on web and the local evaluateConnection flag on iOS. Caveat: on iOS the fix reaches devices only after the SLD viewer OTA bundle is republished per environment.

### QA Review

Environment: Dev + QA (already live in prod via the #1629 hotfix).

* Web SLD editor: open an asset with a terminal that has no connections yet; create a connection to that unwired terminal. The terminal dot and the edge must render immediately, snapped to the port, with no page refresh (previously the edge drew onto the node body).
* Verify parent↔child edge creation also shows the port immediately.
* Attempt "Connect directly" in a configuration that would leave a bus-to-bus chain with no impedance between two buses — the action must now be disabled/blocked (web reads the backend preview flag).
* Negative case: already-wired terminals still connect exactly as before; no duplicate or orphan terminals are created; existing connections still load correctly on reopen.
* iOS (not required for web sign-off): once the SLD viewer OTA bundle is republished per env, confirm the same immediate-render and bus-to-bus block on device.

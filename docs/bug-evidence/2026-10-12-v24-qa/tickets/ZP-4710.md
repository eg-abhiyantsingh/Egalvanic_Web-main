# ZP-4710 — [Web] Asset readings, thermal baseline, direct record entry & flat IR photo storage (Tasks #125/#132/#133)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, backward-compatibility, frontend, migration, schema, ui

## Description

### What's the problem

Meter readings existed only as free-form JSON buried inside a Thermal Anomaly issue, so there was no structured per-asset history and no way to track a component's temperature over time. IR photos, ultrasonic scans, torque logs and fluid samples could only be entered from inside a work order, never directly on an asset. IR files were stored under the capture session's folder, so uploading the same camera file name twice on one asset collided and overwrote. On the asset page the tab bar had also grown too wide to use.

### What's the solution

* Readings (#125): new readings / reading_values tables (per-phase current, millivolt drop, phase-to-phase voltage) with CRUD routes and an idempotent backfill migration that lifts existing values out of Thermal Anomaly issue JSON (the issue JSON is left intact); the three readings props are removed from the Thermal Anomaly class definition.
* Thermal baseline (#125): AI boxes and names the key components on an IR photo, temperatures are read from the radiometric data in code (per-surface rule), and components are re-found on later photos for trend tracking - new thermal_components / thermal_observations / thermal_photo_analyses tables and GET/POST /node/<id>/thermal\[/analyze\], PUT /thermal/components/<id>.
* Direct entry (#132): records created outside a work order are filed under the asset's pseudo work-order id; which record sections appear is driven by service eligibility.
* Flat IR storage (#133): IR files move to ir-photos/{company}/{photo id}/... with server-minted keys and a keyless create-first /ir_photo/create; the row carries service_id and a nullable ir_session_id.
* Frontend: a new Infrared tab (IR + visual layers side by side, Analyze with AI, key-areas table with latest temp / change-since-first / trend, per-area chart, fullscreen picker, multi-photo Compare), a Readings section with add/edit, direct Add IR Photos on the asset, and the Maintenance / Inspections / Infrared / Ultrasonic / Torque / Fluid tabs folded into one Maintenance hover menu.
* Backward compatibility: the FLIR camera app's legacy request bodies are unchanged (pinned by tests) and typed photo numbers keep the legacy create path so web / SD-card uploads still match by name.

Caveat: reporting lambdas do not yet resolve the new storage keys or a NULL ir_session_id (handled separately), and /ir_photo/update/<id> plus the extract-visual routes still lack an explicit tenant check (pre-existing).

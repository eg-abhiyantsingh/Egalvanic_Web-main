# ZP-4587 — Fix ~1 GB EG-form load on every site sync (SLD payload) and bring backend test suite to green (Task #77)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, optimisation

## Description

### What's the problem

iOS site switches were returning 502s on dev. Every site sync builds the SLD payload (/sld/v2, /sld/v3), which listed each EG form's mapped node-class and subtype names by loading every MappingEGFormNodeClass model. Their lazy='joined' relationships pulled the full form and node-class JSON definitions for \~11,900 mapping rows, so every site load cost about 1 GB of memory and \~9 s regardless of site size - enough to OOM-kill gunicorn workers mid-request.

Separately, 135 backend tests had rotted on cicd/dev because no CI workflow runs pytest. The rot included the site-scope security suite, which crashed before asserting anything.

### What's the solution

Replaced the model-loading SLD lookup with a single names-only query (eg_form_id, NodeClass.name, NodeSubtype.name) using outer joins, so a mapping whose class or subtype is gone behaves as before. Verified on dev data (demo, egal, EG-ACME): identical node_class_names / node_subtype_names across all 1,131 forms at 0.24 s vs 9.7 s; empty-site load dropped from \~1 GB (OOM) to a 365 MB process peak at 3 s.

Hardening alongside: added the @require_same_company_account tenant gate to the account access-list, contacts-map and primary-contact routes (previously handler-checked only), and closed a real gap by adding it to DELETE /users/<id>/internal-account-assignments/<account>, which had no company check. Staff routes stay exempt (cross-tenant by design). Stale tests were brought up to date with intentional prior changes; the full suite is now 2,796 passed / 13 skipped / 0 failed (rebased on #1439).

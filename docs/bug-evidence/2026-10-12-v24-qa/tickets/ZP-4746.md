# ZP-4746 — SKM export: generate arc-flash label numbers from bus location

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, ui

## Description

### What's the problem

SKM-exported buses carried no arc-flash label number (AF_LabelNumber), so whenever an arc-flash study was run in PTW, every bus's arc-flash label had to be numbered by hand. On sites with many buses that sit in the same room, this was slow and easy to get wrong, and the export gave no way to derive those numbers from where each bus physically sits.

### What's the solution

SKM export gained an opt-in flag: POST /sld/<id>/export-skm?af_label_from_location=true (default off) stamps AF_LabelNumber (field id 21364797) on every Bus, and on DCBus (field id 38338583) where the DC field tables exist. The value is built from the node's room hierarchy Building/Floor/Room, falling back to the free-text location, with whitespace collapsed and a / inside a name replaced by -. Buses that share a location are suffixed -1, -2, ... in component-name order (a lone bus still gets -1). A label already on the bus (e.g. from a prior SKM import) is preserved. The export writes the AF\_ input field, not AFWC_LabelNumber (21364799, PTW's worst-case result). The web UI adds a checkbox to turn the option on at export time.

Caveat: shipped as a prod hotfix (originals backend #1508 and frontend #1705 merged to cicd/prod), then cherry-picked into cicd/dev via the PRs below. As of this ticket it is in prod and dev but NOT yet in cicd/qa.

### Fixes

* eg-pz-backend #1511 - SKM export: opt-in arc-flash label numbers from bus location (#1508)
* eg-pz-frontend #1708 - UI SKM export: option to generate arc-flash label numbers from location (#1705)

### QA Review

Environment: cicd/dev only (not yet in QA); the feature also shipped to prod as a hotfix.

* On an SLD whose buses have the room hierarchy set, run SKM export with the new 'generate arc-flash label numbers from location' option ON; open the exported file and confirm each Bus has AF_LabelNumber = Building/Floor/Room.
* Put two buses in the same room -> confirm they export as ...-1 and ...-2 in component-name order; a single bus in a room -> ...-1.
* A bus whose node has only a free-text location (no room hierarchy) -> the label falls back to that location text.
* A room/location name containing a / -> confirm it renders as - and the exported XML is still valid.
* Export a bus that already carries an AF_LabelNumber (e.g. from a prior SKM import) with the option ON -> confirm the existing label is kept, not overwritten.
* DC buses: on an SLD with DC buses, confirm AF_LabelNumber is stamped where the DC field tables exist.
* Negative: run the export with the option OFF (the default) -> confirm no AF_LabelNumber is added and the output is unchanged from before.

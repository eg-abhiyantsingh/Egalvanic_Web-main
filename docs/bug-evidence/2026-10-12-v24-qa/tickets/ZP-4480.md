# ZP-4480 — Workhorse model -> AI_WORKHORSE_MODEL: upgrade default LLM to Sonnet 5.5 across backend and AI pipeline

Status: Ready for QA · Assignee: Eric Ehlert · Labels: backend, backward-compatibility

## Description

### What's the problem

The default 'workhorse' LLM (Sonnet 5) was hardcoded in seven backend call sites and in every AI-pipeline lambda plus the runner, and CI had also seeded a copy of it into each lambda's per-flow env vars. Moving to a newer model meant grepping routes by hand and hand-editing every environment's lambda config - slow and error-prone.

### What's the solution

Introduce a single AI_WORKHORSE_MODEL env var (default claude-sonnet-5-5). Backend adds app/services/ai_models.py WORKHORSE_MODEL, used by report-config generation + the tool loop, the EG-form advisor, the /llm Claude provider, the nameplate agent and the asset agent; agent_server.py reads the same var inline. AI pipeline: reconcile_lambda_env.py now writes the CI-owned AI_WORKHORSE_MODEL on the doc-extraction, service-spec and agent-runner lambdas, drops stale per-flow seeds equal to a past/present workhorse, and reports removed keys; lambdas and runner fall back to the env var. Sonnet 5.5 is priced at $2/$10/$2.50/$0.20 in ai_pricing and all 6 ai_usage copies. Backward-compat preserved: Sonnet 5 stays in the pricing table so historical rows still price, and existing overrides still win (ASSET_AGENT_MODEL, NAMEPLATE_AGENT_MODEL, per-flow pins, Opus on the resolution agent). Caveat: the Fargate agent-runner task defs and the classic asset-agent lambdas are not CI-reconciled and were updated by hand; the backend Terraform task defs carry no model mapping, so the code fallback is the effective value in every env.

### Fixes

* eg-pz-backend #1388 - Workhorse model -> AI_WORKHORSE_MODEL (Sonnet 5.5)
* eg-pz-engineering-ai-pipeline #132 - Workhorse model -> AI_WORKHORSE_MODEL (Sonnet 5.5)

* Set AI_WORKHORSE_MODEL to a different model and confirm every workhorse call site picks it up; set ASSET_AGENT_MODEL / NAMEPLATE_AGENT_MODEL and confirm those overrides still win.
* Verify the AI cost ledger prices Sonnet 5.5 rows at $2/$10/$2.50/$0.20 and that historical Sonnet 5 rows still price correctly.
* Pipeline: run a reconcile_lambda_env deploy and confirm doc-extraction/service-spec/agent-runner lambdas get AI_WORKHORSE_MODEL, stale Sonnet-5 per-flow seeds are removed, and deliberate pins are left intact.
* Negative: confirm no call site sends temperature, disabled thinking or a forced tool_choice that would break on 5.5 (a live messages.create on claude-sonnet-5-5 returned end_turn).

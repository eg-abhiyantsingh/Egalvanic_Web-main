# ZP-4751 — Type-to-search on dataset-backed EG form selects (Web + iOS)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: frontend, ui

## Description

### What's the problem

On EG forms, select fields backed by a dataset (externally-sourced option lists) rendered as a plain, non-filterable list. When a dataset had many options, there was no way to type and narrow the choices, so users had to scroll the entire list to find a value. This slowed form filling on both the web renderer and the iOS app, and was severe enough to be shipped as a production hotfix.

### What's the solution

Added type-to-search filtering to dataset-backed EG form selects. On web (EGFormRendererV2) the select now filters its options as the user types; on iOS (EGFormInputBlocks / EGSelectBlockView) the control became a searchable picker. The change originated as a prod hotfix (frontend #1714 / iOS #714) and was brought back to dev by cherry-pick (web) and back-merge (iOS). On iOS the cherry-pick conflicted because release/dev's EGSelectBlockView had added a users source (a .task loader with options_filter/keep); it was ported by hand so both the search picker and the .task loader are retained.

### Fixes

* eg-pz-frontend #1717 - UI Hotfix: type-to-search on dataset-backed EG form selects (#1714)
* eg-pz-mobile-iOS #715 - UI Hotfix: searchable picker for dataset-backed EG form selects (#714)

### QA Review

Environment: dev only (cherry-picked/back-merged to dev; already in prod, not in the QA branch).

* Open an EG form containing a select backed by a dataset (externally-sourced option list) with many options.
* Web: start typing in the select and confirm the option list filters to matching entries and a match can be chosen.
* iOS: open the same select and confirm the picker is searchable and typing narrows the options.
* iOS regression: confirm a users-sourced select still loads its options (the .task loader is retained) and still filters correctly.
* Confirm the selected value still persists into the form as before.

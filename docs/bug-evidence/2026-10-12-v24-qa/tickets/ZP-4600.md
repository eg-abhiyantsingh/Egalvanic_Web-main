# ZP-4600 — Reproducible SLD viewer OTA publish script (per-env, worktree-isolated)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: frontend

## Description

### What's the problem

There was no reproducible, environment-aware way to build and publish the iOS embedded SLD viewer OTA bundle. It had been published with throwaway local scripts (upload-sld-viewer-dev/prod.sh) that have since disappeared, and the process required hand-copying a .env for the GoJS license. Worse, since the lazy-route split (ZP-4189) the mobile build emits \~9 index-\*.js chunks, and SldViewerAssetManager.updateIndexHtmlPaths ignores manifest.json and points the bundled index.html at the last index\*.js it enumerates — so a naive build would ship a bundle that loads the wrong entry chunk and the viewer would break on device.

### What's the solution

Adds scripts/publish-sld-viewer.sh <dev|qa|stag|prod|bces-iq> \[--dry-run\] \[--yes\] \[--version V\] \[--ref REF\]. It builds origin/<env branch> in a temporary detached worktree so the caller's checkout is never touched, builds with that env's frontend secret (GoJS key + API base), and uploads with that env's backend SLD_UPLOAD_API_KEY. It forces FLOW_ONLY_MODE=true in the copy (the ZP-1050 hardcode). The build is OTA-only (inlineDynamicImports + no sourcemaps, layered over vite.config.js) and the script refuses to publish unless there is exactly one index\*.js / index\*.css and the GoJS key is present in the bundle — directly guarding against the wrong-chunk failure above. prod and bces-iq require an explicit --yes. Deliberately not wired into CI (manual, gated publish for now).

### QA Review

Environment: dev only (merged to cicd/dev, not yet in cicd/qa).

* Run scripts/publish-sld-viewer.sh dev --dry-run and confirm it reports exactly one entry chunk, FLOW_ONLY_MODE on, and the GoJS key present in the bundle.
* Confirm the build runs in a temp detached worktree and leaves the caller's checkout clean (git status shows no modified/untracked files after the run).
* Publish to dev and verify on an iOS device that the SLD viewer loads the correct index\*.js (viewer renders, no blank/incorrect chunk).
* Negative: run against prod or bces-iq without --yes and confirm it refuses to publish; and confirm it refuses when a build produces more than one index\*.js or when the GoJS key is missing from the bundle.

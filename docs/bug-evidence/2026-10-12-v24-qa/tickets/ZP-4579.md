# ZP-4579 — Task #73: Torque rules for every asset with a torque table + full-res photos (backend + AI pipeline)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend

## Description

### What's the problem

On an asset with multiple nameplates that each show a torque table (e.g. a panelboard with two breakers), torque rules were being generated for only one device even though every label had a torque table. Three causes sat underneath this symptom:

* The torque-rules model call was capped at 1200 output tokens, so a large table (e.g. 11 rows) ran out mid-response (stop_reason=max_tokens). That empty reply was then cached under the request fingerprint as "no rules", so every later run skipped the asset permanently.
* The torque-rules after_commit hook was imported only in the api APP_MODE, so the mutation worker - which handles every iOS write - never derived rules at all.
* Profile and nameplate photos were sent to the read downscaled (512 px on the backend; the asset-agent additionally pre-filtered and downscaled child/profile/journal photos to \~1100 px) with ratings reading disabled, losing small torque tables.

### What's the solution

* Raised the rules call ceiling to RULES_MAX_TOKENS = 16000 and added rules_complete(): a cut-off or tool-less reply now returns None and the fingerprint is NOT stamped, so the asset is retried instead of cached as empty.
* The torque-rules after_commit hook now loads in every APP_MODE, so mutation-worker (iOS) writes derive rules too, not just the api path.
* Every photo is sent at full detail (API ceiling 2576 px; 2000 px when more than 20 images), profiles readable; the walkthrough classifier and fluid-sample read go full-res as well.
* AI pipeline: the three copies of torque_rules_core.py are synced with the backend; asset-agent drops the photo pre-filter, sends child photos at detail resolution, allows reading ratings on profile prompts, and errors on an incomplete rules reply instead of caching empty; journal-fold MAX_PX raised to 2576.
* Tradeoff: full-resolution photos raise per-request image/token cost; the >20-image path caps at 2000 px to bound it. PR #140 only re-syncs the vendored asset-agent copy that #139 missed, so the deploy's vendored-file check passes.

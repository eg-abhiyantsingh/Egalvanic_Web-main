# ZP-4608 — Queued mobile mutations apply in strict per-SLD order (SQS FIFO)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: backend, migration, schema

## Description

### What's the problem

A site's queued mobile writes could land out of order. The mutation worker applied the inbox by dependency tier using two parallel threads, and a write that failed backed off (up to \~10 minutes) behind newer ones. When ordering slipped, an older full snapshot could overwrite a newer edit â€” silent data loss on a single-line diagram after offline mobile editing.

### What's the solution

Each inbox row is now published to an SQS FIFO queue keyed by lane (its SLD; else the record's SLD; else the company â€” a record keeps its first lane) with dedup id = mutation_id. The worker consumes one message per lane at a time in publish order; a write needing retry holds its lane (visibility pushed to the retry time, the rest of the lane released behind it) while different SLDs proceed in parallel. The inbox row stays the durable record, and a sweeper (advisory-locked) re-sends any publish that failed after commit, in arrival order. Mode is per-environment and switchable without a deploy via SSM /eg-pz/mutations/<env>/queue_url (infra/bootstrap_mutation_queue.sh --enable/--disable); absent = the old DB-polled worker. No IAM change. Additive, nullable migration mqueue_a1 adds mutation_inbox.lane and enqueued_at with a partial index.

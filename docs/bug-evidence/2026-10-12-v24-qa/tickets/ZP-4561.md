# ZP-4561 — Site walks release to assets: POST /site-walk/<id>/release replaces Export to Quote (task #45)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, migration, schema, ui

## Description

### What's the problem

A completed site walk's only path onto a site was Export to Quote → release that quote; there was no way to turn a walk directly into assets. Count walks forced a pricing step, and neither journal nor count walks could mint the assets, connections, photos and implied units they described without going through a quote.

### What's the solution

New POST /site-walk/<id>/release (site_walk_release_service) materializes a node per unit: class/subtype, label, the walk's room plus the typed position as location, nameplate values via the capture-menu writer, the condition assessment, the walk's photos and the class's terminals. Journal walks also get structure — nested units become child nodes (parent_id, relative x/y) and real edges are wired from containment plus proposal_side (main → board, board → feeder, load-side → line-side terminals); an edge with no free terminal is reported (unwired), not stacked. Implied units are created and annotated. Count walks mint one node per counted slot with no wiring.

Release is additive and idempotent: live bindings/nodes are reused, existing edges left alone, one release per walk at a time (SELECT ... FOR UPDATE). A count walk already released through a quote reuses those assets via the pricing-service unit id. GET /site-walk/<id> (and the PUT response) now carries release = {units, pending_units, pending_connections, custom, last} as a preview. The frontend replaces Export to Quote with a single "Create assets" button/dialog (SiteWalkRelease.jsx + useWalkRelease.js) on both walk pages, reads the server's own counts, reports created/unwired/skipped, and removes all pricing from the count page. Migration swjrnl_a8 adds site_walk_assets.proposal_side. Out of scope: cables, equipment-library binding, re-read rewrites and iOS; existing walk quotes still render/release through /plans/from-site-walk and /evaluate.

* eg-pz-frontend #1597 — UI Site walks: "Create assets" replaces Export to Quote; the count page stops pricing

### QA Review

Environment: dev only (not yet in QA). Backend #1414 must be on dev before the button appears; merge order was #1413 → #1414 → #1597.

* Complete a journal walk and accept the model: confirm "Create assets" appears once nothing is proposed, then click it and verify nodes/edges/photos are created on the site; the dialog names any unwired edges or skipped custom rows.
* Complete a count walk: confirm "Create N assets" appears with no Export to Quote and no pricing (no Estimated service value, no Show calculation); release mints one node per counted slot.
* Re-release the same walk → 0 created (additive/idempotent); live bindings reused.
* A count walk previously Exported to a quote → it finds the quote's assets (0 created / N reused) and keeps its Exported chip and link.
* "Open one-line" when everything is already on the site → makes the walk's site active and navigates to /sld.
* Negative: a walk with no site → button disabled with a tooltip; releasing an unassigned or still-pending walk returns code walk_unassigned / proposals_pending / nothing_to_release (409).
* Migration swjrnl_a8: confirm site_walk_assets.proposal_side was added.
* Unit-id collision (#1423): release a count walk whose base id collides with another line; the id stays only on its owning line (by quote position, first-wins in line order), the other line gets a distinct base|i#<line> id so no two units share an id and none is mis-aliased.

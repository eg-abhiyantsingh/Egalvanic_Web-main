# ZP-4719 — [Web] Staff activity-report endpoint for the internal MCP (Task #136)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend

## Description

### What's the problem

The per-customer usage/activity report existed only as a local Claude Code skill (/customer-report) that reached straight into the prod database and DynamoDB using local developer credentials. The internal staff MCP server holds no credentials of its own, so there was no way to produce that report through the staff MCP tooling -- staff could not pull a tenant's usage and activity numbers without running the local skill by hand.

### What's the solution

Added a staff-only backend endpoint GET /staff/activity-report?start=&end=, gated by @require_eg_staff with the tenant taken from X-Act-As-Company and the call audited, backed by a new service app/services/customer_activity_report.py that ports the skill's gather step: users; sites with live and deleted assets; assets added per day; work orders, tasks and issues by month; and customer actions sourced from the edit log (mutation_inbox, before 2026-09-16) and the DynamoDB activity ledger (eg-pz-activity-events-ohio, from then on), bucketed by day, user and site. eGalvanic staff are excluded from the tenant aggregates and counted separately, and only aggregates are returned. Ranges are validated (YYYY-MM-DD, start <= end, at most about 3 years); a bad range returns 400 invalid_range. No migration and no infra change -- the backend task role already holds dynamodb:Query on the ledger table. The consumer is the eg-pz-mcp-internal get_customer_activity / render_customer_activity_report tooling. Carry-forward caveat: the work branched from cicd/prod because it was needed in prod first, then was cherry-picked up to stag, qa and dev, so it reached prod ahead of the usual dev -> qa flow (now present on dev, qa and prod).

### QA Review

Environment: dev + qa (also already on prod).

* As an eGalvanic staff user, call GET /staff/activity-report?start=YYYY-MM-DD&end=YYYY-MM-DD with X-Act-As-Company set to a tenant; confirm 200 with aggregate blocks: users, sites (live + deleted assets), assets added per day, work orders/tasks/issues by month, and customer actions bucketed by day/user/site.
* Confirm eGalvanic staff activity is excluded from the tenant aggregates and reported as a separate count, and that only aggregates (no row-level PII) are returned.

* Confirm the eg-pz-mcp-internal consumer (get_customer_activity / render_customer_activity_report) renders a report through the endpoint for a sample tenant and date range.

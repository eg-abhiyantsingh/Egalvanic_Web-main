# ZP-4532 — Fluid Sample Analysis: typed results, per-asset API, web tab + offline iOS (task #14)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, migration, schema, ui

## Description

### What's the problem

Transformer-oil / insulating-fluid lab results had no typed home in the product. Fluid sample analysis lived in a free-form global form (plus a separate Furan Analysis form), so results could not be read back per asset, compared over time, banded against IEEE/industry limits, or surfaced in reports. There was no per-asset Fluid Samples view, no API to read or write a sample for an asset, and nothing on iOS; assessments like TDCG, total dissolved gas, CO2/CO ratios, estimated degree of polymerisation, and C57.104 condition were not computed anywhere.

### What's the solution

Fluid sample results are now typed rows (fluid_sample_results), written by the EG form and readable per asset, in reports, and on iOS. Assets become eligible via a new fsa_eligible flag on node class or subtype. On every write the server computes TDCG, total gas, CO2/CO, estimated DP (Chendong), IEEE C57.104 condition, an overall band and per-analyte bands against C57.104/C57.106 limits. The global FSA form is rebuilt in place (Sample / Select Tests / one section per test / Assessment) with record_sink=fsa so the projector writes only checked tests; the old Furan Analysis form and its DGA-service method are retired (0 instances on every env). A new per-asset API (/node/<id>/fluid-samples, /fluid-samples/<id>) is tenant-gated through the node's SLD, requires nodes.manage on writes, locks form-sourced rows (409), bounds every number and date, and supports Add-by-AI extraction (Sonnet; PDF/image/CSV/Excel; add-only; source file kept as an asset attachment). The web Asset Details page gains a Fluid Samples tab, and iOS gets offline-first read-only sample cards synced from the site bundle. Caveat: server-published report templates and migrations are deploy-order sensitive (see Migration note).

Follow-up (iOS build fix): #652 added the Fluid Samples card with .assetDetailSection while #657 (ZP-4520) had already renamed that modifier to the generic .detailSection; each PR built alone but release/dev failed to compile once both merged. iOS #666 points the one FSA call site at .detailSection(.fluidSamples, …). No behaviour change.

### QA Review

Environment: Dev only (not yet in QA).

* Eligibility: on a node class or subtype set fsa_eligible (e.g. Oil-Filled Transformer = true, plain Transformer = false); confirm only eligible assets show the Fluid Samples tab on web and the Fluid Samples card on iOS.
* Form -> row: fill and submit the global Fluid Sample Analysis form; confirm a typed row appears on the asset's Fluid Samples tab with computed TDCG, total gas, CO2/CO, estimated DP, overall band and out-of-limit analytes coloured.
* Draft behaviour: edit a submitted instance and confirm the row updates; start a draft and never submit and confirm no row is written; confirm one stable row id per instance.
* Per-asset API: add a manual sample, edit it, delete it; confirm a form-sourced row is locked (409) and cannot be edited via the asset UI; confirm number/date bounds reject out-of-range values (dates outside 1950..tomorrow).
* Add by AI: upload a PDF/image/CSV/Excel to one asset, review the extracted values before save, confirm add-only behaviour and that the source file is attached to the asset.
* Reports: run flask publish-fsa-templates then generate the asset's report; confirm the FSA report page renders with sample history.
* iOS: with the device offline, open an eligible asset and confirm the read-only Fluid Samples card shows condition badges, the out-of-limits filter works, and strings render in en and fr; confirm a retracted (soft-deleted) sample disappears after sync.
* Negative: confirm the retired Furan Analysis form is gone and that a bool stored in a numeric analyte is treated as empty (not resent as false).

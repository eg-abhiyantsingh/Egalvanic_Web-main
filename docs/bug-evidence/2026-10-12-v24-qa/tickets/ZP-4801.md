# ZP-4801 — Task #160: IR photos - thermally_tuned flag + Tuned checkbox in the work order (TKT-1439)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, migration, schema, ui

## Description

### What's the problem

Back office tunes each IR (thermal) image's level and span before reporting (TKT-1439, P&H Electrical) but had no way to mark which images were already done, so there was no tracking of which IR photos were report-ready.

### What's the solution

Added a thermally_tuned boolean to IR photos via migration irtuned_a1 (parent noticecc_a1, single head: ir_photos.thermally_tuned BOOLEAN NOT NULL DEFAULT FALSE, IF NOT EXISTS), surfaced it on IRPhoto.to_dict so it flows to the work-order IR Photos grid, and added PUT /ir_photo/<id>/thermally-tuned {thermally_tuned: bool} guarded by the ir_photos.upload permission and tenant-scoped via the photo's SLD (falling back to its node's SLD for rows with no sld_id; other tenants' ids return 404), recording an ir_photo.thermally_tuned activity event. The frontend adds a Tuned checkbox column after the image columns in the work-order IR Photos grid, with an optimistic toggle that reverts with a toast on failure, disabled without ir_photos.upload and locked with the rest of the tab on a closed work order.

### Fixes

* eg-pz-backend #1534 - IR photos: thermally_tuned flag + PUT /ir_photo/<id>/thermally-tuned (task #160)
* eg-pz-frontend #1731 - UI IR photos: Tuned checkbox per photo in the work order (task #160)

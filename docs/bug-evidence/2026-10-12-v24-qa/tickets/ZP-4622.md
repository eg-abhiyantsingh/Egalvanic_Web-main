# ZP-4622 — Task #101: Per-view terminal/elbow manips round-trip between the iOS-bundled SLD viewer and backend

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, schema

## Description

### What's the problem

Per-view terminal slots never reached the iOS app. iOS reads view mappings from MappingNodeSLDView.to_dict (GET /sld/v2 -> mappings.node_sld_view), which omitted node_manips, so per-view terminal positions were dropped even though edge view mappings already carried edge_manips. On the write side, under the iOS bridge the viewer's saveNodeManips / saveEdgeManips returned early with no message, so terminal moves and pinned elbow bends made on iOS were never saved.

### What's the solution

Backend adds node_manips as an additive field on MappingNodeSLDView.to_dict so per-view terminal slots ship in the GET /sld/v2 view mapping (mirroring the existing edge_manips). Frontend: the iOS-bridge viewer now posts graphUpdate messages - nodeManipsChanged {id, manips} as a merge-patch and edgeManipsChanged {id, manips} for the whole chain (null clears) - so terminal and elbow edits persist; older apps ignore unknown message types. The native iOS side ships separately on release/dev and the bundled viewer needs an OTA republish per environment.

### Fixes

* eg-pz-backend #1464 - Task #101: per-view node_manips in the view mapping dict
* eg-pz-frontend #1648 - UI Task #101: iOS viewer reports terminal / elbow edits to the app

### QA Review

Environment: dev only (not yet in QA).

* On dev, open an SLD in the iOS-bundled viewer and confirm per-view terminal slots (node_manips) now render; they were previously missing from GET /sld/v2 mappings.node_sld_view.
* On iOS, move a terminal or pin an elbow bend and confirm it persists after reload (nodeManipsChanged / edgeManipsChanged posted over the bridge).
* Confirm clearing an elbow chain (edgeManipsChanged with null) removes the pinned bends.
* Confirm older app builds ignore the new graphUpdate message types without error.
* Note the bundled viewer requires an OTA republish per env, and the native iOS change ships in a separate release/dev PR.

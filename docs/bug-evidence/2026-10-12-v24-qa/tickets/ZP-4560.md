# ZP-4560 — Lock EG Form record-sink keys + blueprint-owned FSA/torque eligibility (task #67)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, migration, ui

## Description

### What's the problem

FSA Sample and Torque Log blocks project EG Form answers into typed tables (fluid_sample_results, torque_records), keyed by field. Any form save — the builder, its AI agent, staff/MCP saves, or company service-version apply — could rename or drop one of those keys and silently stop the typed records from being written, with no error surfaced.

Separately, FSA/torque eligibility was freely editable on global-derived (override) classes and subtypes, and Cable and Fuse were torque-eligible even though neither has terminations of its own.

### What's the solution

Added a record-sink key lock (record_sinks.sink_key_violations / sink_lock_response) that rejects any save which, inside a kept sink, renames or removes a key (block, child block, or data_table column/row/meta heading), drops the record_sink tag, or changes the sink kind. Label edits, new headings, and deleting a whole sink block stay allowed. It is wired into PUT /eg-forms/<id>, the staff/MCP form save, and company service-version apply (the apply path checks before mutating), returning 400 record_sink_keys_locked. fsa_eligible/torque_eligible are now in LOCKED_ON_OVERRIDE and locked on global/override subtypes; custom classes and subtypes stay editable. The frontend mirrors the rule client-side (recordSinkKeys.js) and locks the builder block dialog and the class-editor toggles.

Migration tqlock_a1 sets torque_eligible=false on the Cable and Fuse globals, their overrides and their subtypes, and strips the hidden "Torque values" prop. Caveat (one-way door): this turns torque OFF on every company's Cable/Fuse override too, and the flag is now locked there — the supported re-enable path is a custom subtype under the class, or a global change via migration.

### QA Review

Environment: dev only (not yet in QA).

* In the EG Form builder, open a Torque Log / FSA Sample block dialog: confirm saved keys (block key, column/row headings, meta) are disabled with a lock note and the table type is frozen.
* Edit only a label → save succeeds (200) and the key is unchanged; the typed record projection still fills afterward.
* Rename a sink key via Form Code → Save is refused with record_sink_keys_locked and nothing reaches the server.
* Add a new heading → allowed; delete a whole sink block → allowed.
* In an override class (e.g. Circuit Breaker) confirm the Fluid Samples / Torque Records toggles are disabled; flipping returns 403, same-value save returns 200; repeat for an override subtype.
* Confirm an AI-agent draft that breaks sink keys disables Accept with the reasons on hover.
* Migration tqlock_a1: confirm Cable and Fuse are no longer torque-eligible and the hidden Torque-values prop is stripped.

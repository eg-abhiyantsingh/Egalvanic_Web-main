# ZP-4481 — SLD Issues: warn on custom asset classes with no device role (uncategorized pass-through)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: frontend, ui

## Description

### What's the problem

A customer-made asset class keeps the default 'uncategorized' device role, which is a pass-through in the SLD connection rules. Every SLD issue check tunnels straight through those assets, so real problems go unflagged and SKM export cannot model them. In prod there are 63 uncategorized custom classes across 13 companies (6,003 live assets) - e.g. seven drives under a home-made 'Inverter' class showed a clean issue list.

### What's the solution

Add one new SLD issue, class.uncategorized (severity warning), raised once per SLD (not per class or per parent). It lists every asset whose class role is explicitly 'uncategorized', carries an uncategorized-assets.csv (Asset, Asset Class, Parent Asset) through the existing generic CSV link in IssuesWidget, and names the company in the copy (falls back to 'your company' in the embedded iOS viewer where there is no signed-in web user). A class payload with no role at all is not flagged, so a thin payload cannot flood the list. Caveat: the LOTO menu item is gated on the SLD having no error/warning issues, so an SLD with uncategorized classes now blocks LOTO generation until the assets are moved; the file lives under src/sld/, so iOS picks this up only after the SLD viewer OTA bundle is republished per environment. Landed as prod hotfix #1566 cherry-picked to cicd/dev.

### QA Review

* Environment: dev only (cicd/dev; cherry-pick of prod hotfix #1566, not in cicd/qa).
* On an SLD with assets in a custom class using the 'uncategorized' device role, confirm a single class.uncategorized warning is raised (once per SLD) listing those assets, with a downloadable uncategorized-assets.csv (Asset, Asset Class, Parent Asset).
* Confirm the warning copy names the company; in the embedded iOS viewer confirm it falls back to 'your company'.
* Confirm LOTO generation is blocked while uncategorized-class warnings stand, and unblocks once assets are recategorized.
* Negative: a class payload with no role at all must NOT be flagged; an SLD with no uncategorized classes raises no issue.

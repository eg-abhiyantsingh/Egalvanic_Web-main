# ZP-4585 — Cross-company guest access: invite users from other companies as guests with scoped roles and sites (Task #77)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: api, backend, frontend, migration, schema, ui

## Description

### What's the problem

A user belonged to exactly one company, so another company could not grant them access to its sites and work orders. The tenant gate failed closed whenever the acting (X-Subdomain) company differed from the user's own company_id, and a user's home roles would have applied unchanged in any company they reached. There was no way to invite someone from another company as a guest, no way for an invited user to reach the host company from the web app, and no admin surface to manage guests.

Separately, while building this, two pre-existing tenant-isolation gaps surfaced: an admin-only GET /ir_session route listed every company's work orders with no company filter, and @require_sld_access plus assigned-site checks treated admins as able to reach any site id regardless of company.

### What's the solution

Adds a cross-company guest-access system gated by LaunchDarkly flag feature-guest-access (unknown = off; dev-only target EG-ACME, no production targets). Core pieces:

* New company_guest_memberships table (migration guest_a1): host company + guest user + exactly one non-admin system role (Electrical Engineer / Project Manager / Account Manager / Technician), lifecycle invited -> active -> revoked/declined. Assigned sites are ordinary mapping_user_sld rows on host SLDs.
* Guest context bound in require_auth, require_auth_v2 and the mutation middleware: token verified against the guest's HOME pool, deny-by-default allowlist (GUEST_ENDPOINTS), RBAC returns ONLY the granted guest role so home-admin roles never cross over, and every company read routed through acting_company_id().
* New /guest-access/\* routes (host: invite/list/update/revoke; guest: workspaces/accept/decline/leave; single-use 60s hashed handoff/redeem + switch). /auth/v2/me reports the host company, its features/branding and a guest block. Assignee pickers gain include_guests.
* Web: company switcher on the brand mark, Admin > People > Guests (invite/edit/revoke), one-time handoff-code switching with a full reload, an in-app invite toast, guest sign-out returns to the home host, and Customers is hidden and access-denied for guests.
* Hardening applied for everyone (not flagged): deleted the unscoped GET /ir_session; @require_sld_access (52 routes) now requires the site to belong to the caller's company; assigned sites only count within the acting company.

Tradeoff to carry forward: an invite email + Resend were added (BE #1435, FE #1625) then deliberately replaced by an in-app notification (BE #1436, FE #1626), so the net behaviour is in-app notification only. Rolls out dev-only under the LD flag; production has no targets.

### QA Review

Environment: Dev only (cicd/dev). feature-guest-access is ON for EG-ACME in dev; verify behind the flag.

* Flag off: as a company NOT targeted by feature-guest-access, confirm there is no switcher, no Admin > People > Guests page, and that /guest-access/\* routes deny.
* Invite: as a host admin (EG-ACME) with users.manage, invite an existing user of another company with ONE role and selected sites; confirm an admin user cannot be granted a guest role.
* Accept + switch: as the invited user, sign in to the HOME company, see the in-app invite toast (Review opens the switcher on the brand mark), accept, then switch to the host; confirm a full page reload and that only assigned host sites are visible.
* Role isolation: as the guest, confirm menus/profile show ONLY the guest role (not home roles), and that Site Overview, Condition Assessment, Planned Work, and the asset-page Maintenance Program / Add Service History dialogs load without the '<!DOCTYPE ... is not valid JSON' error.
* Negative - Customers: as a guest whose role holds accounts.view (EE/PM/AM), confirm the Customers nav entry is hidden and /customers shows Access Denied; confirm Sales/Operations/Builder menus and the full customer account list are not reachable.
* Tenant isolation: confirm GET /ir_session is gone (404), and that an admin cannot reach another company's sites through @require_sld_access routes.
* Sign-out + handoff: guest sign-out returns to the home company's host; confirm the one-time handoff code is cleared from the URL/history after switching.

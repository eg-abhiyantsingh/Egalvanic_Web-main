# ZP-4570 — Quick photo view for assets on the GoJS SLD (task #23, TKT-865)

Status: Ready for QA · Assignee: Eric Ehlert · Labels: frontend, ui

## Description

### What's the problem

Viewing an asset's photos from the single-line diagram (SLD) meant leaving the diagram and navigating to the asset page — a disruptive context switch for anyone reviewing a site's one-line (TKT-865, CECCO).

### What's the solution

Adds an in-diagram photo preview and gallery on the GoJS SLD. Resting \~1s on an asset node (including enclosures; not links/groups/buses) opens an MUI Popper beside it with asset name, class, photo count and up to 4 thumbnails (+N), plus "No photos"/"Photos unavailable" states; it stays while the pointer is on the card and dismisses on leave (300ms grace), any press, wheel, or pan/zoom.

A full gallery dialog (ZoomPanImage zoom/pan, prev/next + arrow keys, thumbnail strip, download, "Open asset page" in a new tab) opens from a thumbnail, the gallery icon, or the node context-menu "View photos" (context menu only when editing is unlocked — unchanged lock behavior). Hover detection wraps the GoJS ToolManager's doMouseHover/Move/Down/Wheel, calling the originals first — no input consumed, no node-template changes.

Data uses existing endpoints only (GET /photo/by_entity/<id> + getPhotoUrlsBatch, same as AssetPhotoSidePanel), fetched lazily after the dwell completes and cached per node for 30 min. Disabled under flowOnlyMode / window.FLOW_ONLY_MODE / the iOS WebKit bridge and when the editor surface is inactive (no OTA impact); enabled in the Maintenance Portal read-only one-line intentionally. en + fr strings.

Verification — Work Order Details: paginate all content sections

Ticket: “[Web] Work Order Details — Paginate all content sections (Assets, Issues, Tasks, Photos, Attachments)”  ·  Environment: QA acme.qa.egalvanic.ai (app badge V1.36)  ·  Page verified: /sessions/{id} (Work Order Details)  ·  Verified: 2026-07-31, authenticated Super-Admin session

✅ IMPLEMENTED — all five named sections are server-side paginated with controls and total counts. Each section lazily calls a versioned /v2 endpoint with limit + offset, renders a “Rows per page / 1–N of N” footer, and shows a total count in both the tab badge and the section heading (e.g. “IR Photos (8)”). One residual gap: the Forms sub-tab is still unpaginated.

Each section fetches lazily on tab activation (verified by diffing performance.getEntriesByType('resource') before/after each tab click) — so opening a work order no longer downloads every section's rows up front. Additionally a GET /ir_session/{id}/summary/v2 supplies the per-section totals (counts: {assets, issues, tasks, photos, attachments, asset_nodes}) without fetching rows.

h3. QA result (stage hotfix): PASS for the web fix. The last step is not covered (the reset email did not arrive)

*Tested on:* stage https://acme.stage.egalvanic.ai, build index-Cx_eO71S.js, which contains eg-pz-frontend PR #2032 (merged to cicd/stag 16 Nov 15:36 IST). 16 Nov 2026, 16:00–16:20 IST, Chrome on macOS, stage Electrical Engineer test seat.

*Simple explanation:* the Reset Password page no longer blocks a password that has #. Before the fix the page itself refused it, because only @ $ \! % * ? & counted as special characters. Now a password with # is sent on to the server, and the error message lists example special characters.

*Steps*
# Sign-in page › email › Use my password › Forgot your password? › Send Reset Code.
# Type a new password with no special character (Kroonstage5288) › Reset Password.
# Type a new password with # (Kroon#Stage…) and the code 000000 › Reset Password.

|| Check || Result || Status ||
| Password with no special character | Refused on the page with the new text "Password must contain an uppercase letter, a lowercase letter, a number, and a special character (e.g. \! @ # $ % & * ? -)". Nothing is sent to the server (screenshot 1). | PASS |
| Password with # | The page accepts it and sends POST /api/auth/reset-password. The server only answers "Invalid verification code provided" (000000 is a dummy code), with no password-rule error (screenshot 2). | PASS |
| Same rule on Forgot Password and Register | PR #2032 moves both forms to the new check. /register is not reachable on stage (it shows the sign-in page), so only Forgot Password was tested in the browser. | PASS (Forgot Password) |

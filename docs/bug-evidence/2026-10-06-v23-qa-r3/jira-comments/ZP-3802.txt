*What happened*
* Typing shows Google suggestions (one request after three letters). Picking one fills the fields and the block verifies by itself: chip "Verified", a map, "Updated to Google's version of this address." (ZIP became 94043-1351), and a Google photo of the place with "Use this photo" / "Upload my own". Create stays disabled until the address is verified.
* Changing the city makes the chip "Verifying…" and disables Create again; restoring it returns to "Verified" with no new request.
* Create saves the account and the site with Google's canonical address, the coordinates and the verification details, and stores the chosen Google photo as a reference with its attribution. One request each for suggestions, place details, verify and photos; no extra Google call on save.
* The site page shows the map, "Google view" (the chosen photo), a "Site photo" slot with the empty state "No site photo — Crews won't have a picture of the entrance.", the address with the Verified chip under it, the coordinates with "Verified Oct 06, 2026", access complexity, created date, and the Location, Access and Notes cards.
* Edit Customer: the account's address has its own Verified chip and map. Changing Address line 2 shows "Re-verify needed — The address changed after it was verified. Verify again before saving." but Save Details stays enabled; after saving, the server re-verified the address itself (stored as entered, coordinates kept).
* No match: Verify address shows "Not verified — Google could not find this address. You can still save it as entered — it just will not carry coordinates, so dispatch and routing cannot use it." Create stays enabled once every required field is filled, and the site is saved without coordinates, status "no match".
* *Gap (item 2):* when the typed address differs from Google's (lowercase, or the misspelled "Amphitheater Parkway"), the build replaces the fields with Google's version and shows the note. It never offers to keep the address as entered.

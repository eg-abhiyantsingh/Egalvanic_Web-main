*Result: PASS (backend/API).*
* All 7 tables in the ticket now carry created_by and modified_by, and their API payloads return both.
* A create stamps the user who made the call. An edit by a different user changes modified_by and leaves created_by alone.
* Values sent by the client are ignored. Rows from before the change stay null.

*Build:* QA index-oFAZQ3rK.js, 17 Nov 2026, 11:30–11:40 IST. Seats: Account Manager and Project Manager (sales records), Super Admin and Admin (labor rates, materials, subcontractors). The ids are users.id, which equals each seat's sub in /api/auth/v2/me. Fix: eg-pz-backend PR #1812. No feature flag.

*Steps (the API calls the web app makes)*
# quotes + opportunities: Account Manager creates a quote with POST /api/quote/create-standard (Opportunities › New Quote).
#* Quote and its opportunity: created_by = modified_by = Account Manager.
#* Project Manager renames both (PUT /api/quote/update/\{id\}, PUT /api/opportunity/\{id\}): created_by stays Account Manager, modified_by = Project Manager. PASS.
# quote_labor: Account Manager POST /api/quote-labor/create; Project Manager PUT /api/quote-labor/update/\{id\}. Account Manager / Project Manager. PASS.
# quote_labor_lines: Account Manager adds a manual labor line (POST /api/workorder/\{id\}/labor-lines); Project Manager saves it (PUT …/labor-lines/bulk-save). Account Manager / Project Manager. PASS.
# labor_rates, materials_library, vendors: Super Admin creates them (POST /api/labor-rates, /api/materials-library, /api/vendors); Admin edits them. created_by stays Super Admin, modified_by = Admin. The list endpoints return the same values. PASS.
# Spoofing:
#* POST /api/labor-rates with created_by/modified_by set to the Project Manager's id → stored as Super Admin.
#* PUT with both set to the Account Manager's id → stored as Super Admin / Admin.
#* PASS.
# No backfill: the older quote "test new - Rev 1" (12 Jan 2026) and its opportunity are null/null, and so are the older labor rates, materials and subcontractors. PASS.

*Notes (not defects by the ticket's wording):*
# Saving a labor rate with no field changed moves modified_at but keeps the old modified_by, because the stamp only fires on a real change.
# The quote list (POST /api/company/\{id\}/quotes/v2) doesn't include the two fields; the quote detail does.
# No web screen shows these fields yet. Showing them is a later frontend change.

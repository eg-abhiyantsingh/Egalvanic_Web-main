!QA-17Nov-BUG-ios-assembly-placement-loses-hidden-and-elbow.mp4|width=720!
_Video: web read-back of the assembly the iOS app placed on 16 Nov (connection shown as a normal line, no elbow), then the control: the same assembly placed on web keeps the hidden connection and the elbow (29 s)_

*In simple words:* when the iOS app places a saved SLD assembly, the connection that the assembly marks as hidden comes back as a normal visible line on web, and the connection's fixed bend (elbow) is lost. Web placement of the same assembly keeps both. Only the iOS-placed copy is wrong.

*Where:* iOS app › SLD › unlock › Assembly (Task #205, ZP-5102). It shows on web (and on any other device) after sync.
*Environment:* QA, company EG-ACME. iOS 1.75 (release/qa 34bd67e, promoted 16 Nov). Web read-back on build index-LGhrn-48.js, 17 Nov 2026 14:26 IST.

*Steps to reproduce*
# On web, the assembly "QA4942-FDR-\{name\}" holds 4 assets and 2 connections:
#* FUSE nosub → Load-1 is a hidden connection (edge_manips \{"hidden":true\}).
#* CB-2 → PNL-2 has one fixed elbow (edge_manips \{"elbows":\[\[54,493\]\]\}).
# On the iOS app: open an SLD (here Android Site 2), unlock, tap Assembly, pick "QA4942-FDR-\{name\}", name it (here ZP5102), tap Place, then tap the canvas. The iOS tester did this on 16 Nov 13:05 UTC.
# Open the same SLD on web and look at the placed copy: https://acme.qa.egalvanic.ai/slds (site "Android Site 2", assets "QA4942-FDR-ZP5102 …").

*Actual*
* Web draws "QA4942-FDR-ZP5102 FUSE nosub → Load-1" as a normal line, with no hidden-connection badges.
* CB-2 → PNL-2 has no elbow. API: both edges have edge_manips = null.
* The Mutation Audit Log shows why: the iOS "edge create" payloads (mutations ed6d914a…, cab96538…) contain no edge_manips field.

*Expected:* the iOS-placed copy matches a web placement:
* FUSE nosub → Load-1 stays hidden (edge_manips \{"hidden":true\}).
* CB-2 → PNL-2 keeps its elbow.
This is the ZP-4942 rule "routing and the hidden flag kept".

*Control (same assembly, web):* placed today as QA4942-FDR-L2 (POST /api/assemblies/\{id\}/place → 201).
* FUSE nosub → Load-1 has edge_manips \{"hidden":true\} (badges shown).
* CB-2 → PNL-2 has edge_manips \{"elbows":\[\[1035,1322\]\]\}.
* The 12 Nov web placement (L1) is the same.

*What did sync correctly from iOS:*
* The 4 assets, both connections and the group "QA-DEMO ZP-4942 grp 12 Nov QA4942-FDR-ZP5102".
* The order: node create ×4 → edge create ×2 → node_group update.

*Possible cause (iOS source, release/qa 34bd67e):*
* Core/Singletons/APIClient.swift createEdge(edge:) builds SLDDTOEdge(… points: edge.points, algorithm: edge.algorithm) without edge_manips.
* The local EdgeV2 does keep edge_manips_json (SLDSyncService materializes it from the placement DTO), so the device looks right until a fresh sync from the server.
* AssemblyPlacementService sends the edges through this same createEdge, both online and from the offline queue.

*Also check:*
* Android 1.40 (ZP-5112): place the same assembly and read it back on web.
* iOS: after placement, refresh or re-sync the SLD on the device. The hidden connection probably turns into a normal line there too.

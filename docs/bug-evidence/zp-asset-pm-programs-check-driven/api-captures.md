## Consistency note — two endpoints, two answers
For the same work order at the same moment (right after the MOT-3836 tick), five explicit calls `GET /api/ir_session/11b924b8-…/location-readiness/v2?mask=<m>` returned `arc_flash → {Unassigned:{arc_flash:{ready:2,total:10}}}`, `asset_checks → {ready:5,total:10}`, `ir_photos → {ready:0,total:10}`, `checklist → {ready:0,total:0}`, `com → {ready:0,total:10}`, while `service-completion` returned `arc_flash 5/10`, `asset_checks 4/5`, `ir_photos 1/1`, `rooms.Unassigned 10/16`. The two endpoints disagree on every category; the mask endpoint's denominators equal the room's asset count (10) rather than the registered count, and its numerators differ too. **Cause not isolated** — the masks may measure something other than check-off state (e.g. data completeness). The rail does not print these numbers in the current layout.

## Discriminating test added after the adversarial pass — a STATED date LATER than the registry date
Every earlier case had the registry date later than the stated one, so "later wins" and "registry always wins" were indistinguishable. Run 16:35: MAIN-BUS-3836 → Maintenance → SERVICE HISTORY → **Add record** → Service *Infrared Thermography* → Last serviced **2026-09-08** (one day after the registry date 2026-09-07) → Save.
`PUT /api/asset-maintenance/node/6bbb66ac-…/history {"service_id":"4d5ea9cb-…","last_serviced_on":"2026-09-08"}` → 200.
Before: `Infrared Thermography: 12mo due 2027-09-07 last 2026-09-07/registry`. After: **`Infrared Thermography: 12mo due 2027-09-08 last 2026-09-08/stated`**; `history[]` now carries `Infrared Thermography:2026-09-08:stated`. **The later stated date won over the registry date and the due date re-derived from it — the rule really is "later of the two", not "registry first".** (Proven on the history-write path; the plan dialog's `service_dates` path was not re-run with this shape, but both feed the same `schedules[].last_serviced` resolution.) The Add-record dialog's own copy states the rule: "A stated date only moves the record forward if it is later."

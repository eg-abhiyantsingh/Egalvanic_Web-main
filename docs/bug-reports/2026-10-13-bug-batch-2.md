## Bug 1 — [Web] A user not assigned to a site can still change that site's SLD connections and assets

- **Priority:** Medium
- **Labels:** web, security, site-access, sld, qa-13oct
- **Relates to:** ZP-4849
- **Screenshots (folder `docs/bug-evidence/2026-10-13-bug-batch-2/`):** 1-1-pm-sld-connection-hidden-before.png, 1-2-ee-site-not-in-site-list.png, 1-3-ee-read-refused-but-writes-accepted.png, 1-4-pm-sees-change-made-by-unassigned-ee.png, 1-5-pm-restored-after-test.png

**Description (Jira wiki markup):**

```
h3. What happens
A user who is not assigned to a site cannot open that site in the app. But the server still lets that user change the site's one-line diagram (SLD): its connections and its assets. The change is saved, and the people who do have the site see it.

h3. Steps
# Sign in as a Project Manager who HAS the site (QA user abhiyant.singh+project@egalvanic.com). Pick site "QA-DEMO ZP-4800 SLD canvas v2.4 (delete me)" and open Site Data > SLD. The connection "QA-DEMO 4591 SRC CB" to "QA-DEMO 4799 JBOX" is hidden: you see two short stubs with name tags, no line. (Screenshot 1)
!1-1-pm-sld-connection-hidden-before.png|width=720!
# In a second browser, sign in as an Electrical Engineer who does NOT have that site (QA user abhiyant.singh+electric@egalvanic.com; a real customer user, not Egalvanic staff). Open the "Current site" box and type "QA-DEMO ZP-4800": the app shows "No sites available" - the site is not offered to this user. (Screenshot 2)
!1-2-ee-site-not-in-site-list.png|width=720!
# Still as the Electrical Engineer, open Engineering > SLD with that site forced. The app shows "The diagram couldn't be loaded" and the read is refused (server answers 422). !1-3-ee-read-refused-but-writes-accepted.png|width=720!
# Go back to the Project Manager and reload Site Data > SLD. The connection is now a full line again: the Electrical Engineer un-hid it. The asset "QA-DEMO 4799 JBOX" now also carries the Electrical Engineer's test value. (Screenshot 4)
!1-4-pm-sees-change-made-by-unassigned-ee.png|width=720!
# Clean-up: the Project Manager put both values back, so the connection is hidden again. (Screenshot 5)
!1-5-pm-restored-after-test.png|width=720!

h3. What should happen
The server should refuse these saves (422 / 403 permission denied) for any site that is not in the user's assigned sites, the same way it already refuses to read the diagram.

h3. Notes
```

# Asset PM maintenance programs, explicit check-off registry, check-driven completion

**QA verdict — all six web-testable checklist steps PASS on QA. The asset Maintenance tab establishes a program from a Suggested-ranked plan or from directly composed services; per-asset due dates derive from the effective last-serviced (later of customer-stated vs registry) and survive both a line re-tune and a whole-plan replace; the Assets-list bulk configurator applies plans and is gated on a shared asset class, with the legacy PM-designations shortcut gone; the work-order wheel is check-driven — a PM Forms service now carries its own ring and one tick moved it live; the de-energized negative gate fires with `skipped_never_shutdown`. One real defect: in the BULK path that gate is silent — a 4-service plan applied to two never-shutdown assets wrote 1 service each and the "6 de-energized schedule(s) skipped" warning was never shown.**

**Artifact:** https://claude.ai/code/artifact/7f56422d-f1ad-45f7-869e-907c058ba8e4
**Tested:** 2026-09-08 · `acme.qa.egalvanic.ai` build **V1.36**, bundle **`index-CSsDpG3c.js`** · tenant acme · Super Admin seat · live UI clicks + captured API traffic + bundle reading.
**Ticket said the change was dev-only / not yet promoted.** Wrong for the web half: the Maintenance tab, the plan/custom-program dialog, the bulk configurator, the shutdown gate and the service-named completion rings are all live on QA today.

## Findings

### DEFECT 1 (Medium) — the bulk "Apply PM Plans" path drops de-energized schedules silently
**Repro:** `/assets` → Bulk Ops → tick **11N-H1-1** and **12N-H1-1** (both Panelboard) → **Shutdown rules** → "Never" → Apply to 2 Assets → with the same two still selected, **Apply PM Plans** → Replace with a PM Plan → "Panelboard (Generic) — Criticality 1" (4 services, 3 of them de-energized) → **Apply to 2 Assets**.
**Actual:** the bulk dialog shows none of the "Won't be set up — can never shut down" labels the single-asset dialog shows. The apply returns 200 with `schedules_written: 2`, `skipped_never_shutdown: 6`, `warnings: ["6 de-energized schedule(s) skipped on asset(s) marked as never able to shut down"]` — and **no alert, toast or dialog carries that text**. Both assets end with 1 task (Infrared Thermography) after a 4-service plan was chosen for them.
**Expected:** the bulk dialog flags which lines will be skipped for how many of the selected assets, or the response's `warnings[]` is surfaced after the apply, so "I applied a 4-service plan to 2 assets" cannot silently mean 2 schedules.
**Why it matters:** the single-asset warning is what makes the gate safe, and it is exactly the disclosure that disappears at the scale where the gate matters most. On a 50-asset selection the user gets one green close and no indication that a third of the plan never landed.

### FINDING 2 (Low) — flipping an asset to "Never shut down" leaves its existing de-energized schedules live
After the bulk Shutdown-rules change to `never`, both assets still held their full 4-line programs with all three de-energized lines still due; the restriction is only consulted when a program is applied. Those schedules disappeared only because the later replace-apply rewrote the program. Nothing flags a now-impossible schedule on an asset that can never be shut down.

### FINDING 3 (Low) — an undated de-energized line keeps its outage-aligned due date after the restriction is relaxed
On MAIN-BUS-3836, after `planned_shutdowns_only` aligned the de-energized lines to 1 Mar 2029 and the restriction was set back to "Can shut down anytime", NETA re-derived to its natural 1 Sept 2028 but the undated De-Energized Visual Inspection stayed at the outage-aligned 1 Mar 2029 (it has no anchor to re-derive from). It corrected itself only when a registry date arrived. Cosmetic while it lasts, but the two lines disagree about which rule they follow.

### FINDING 4 (Low) — two label sets for the same four shutdown values
The asset page says "Can shut down anytime / … — has a bypass / Planned shutdowns only / Can never shut down"; the bulk dialog says "Whenever needed / Whenever needed — has a bypass / Only during planned shutdowns / Never". Same enum (`unrestricted`, `bypass`, `planned_shutdowns_only`, `never`), two vocabularies in one workflow.

### FINDING 5 (Low) — the plan picker shows identical duplicate labels
Searching "Criticality 2" on a Panelboard returns four rows all reading "Panelboard (Generic) — Criticality 2 · Whole class · 4 services": the NFPA 70B global plan plus one copy per tenant standard. Only the group header distinguishes them, and the headers are easy to lose while scrolling a filtered list. The Suggested group has the same shape (three identically named Criticality 1 plans, differing only by the "from <standard>" caption).

### FINDING 6 (Low, API only) — the Locations rail and the header wheel disagree
For the same work order at the same moment, `location-readiness/v2?mask=…` reported `arc_flash 2/10`, `asset_checks 5/10`, `ir_photos 0/10` while `service-completion` reported `arc_flash 5/10`, `asset_checks 4/5`, `ir_photos 1/1`. The rail counts every asset in the room as its denominator rather than the assets carrying the service, and the numerators differ too. The current layout does not print these numbers, so nothing wrong is visible yet — worth reconciling before the rail starts showing them.

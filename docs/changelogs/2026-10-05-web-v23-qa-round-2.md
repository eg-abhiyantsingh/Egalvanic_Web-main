off-limits. That turned out to be wrong. QA holds **other companies' data outside acme's 247 sites**: 35 sites and 102 work

## Code changes
1. **`src/test/java/com/egalvanic/qa/testcase/QaDriverDaemon.java` (new).** A remote-controlled, signed-in browser for
   manual ticket testing. It extends `BaseTest`, so the login, the 2FA prompt handling, site selection and TLS settings are
   the framework's own. It then polls `-Dqa.daemon.dir/in` for command files (`js`, `get`, `shot`, `click`, `keys`,
   `alert`, `stop`) and writes each result to `out/<name>.txt`. It replaced typing passwords into a browser (not allowed)
   after the claude-in-chrome tab was signed out. It never acts on its own: every action is one command file.
2. **`BaseTest.java`:** a `-Dqa.unhandledPrompt=ignore` switch. By default Selenium dismisses a native `confirm()` on the
   next command, so the daemon could never read or accept the asset-class "Are you sure…?" dialog (ZP-4454). With the
   switch the dialog stays open until the `alert` command handles it. When the property is unset, nothing changes for
   existing suites.

## Learning notes
- **The QA CDN hides refusals.** A 403/404 from the API comes back as the app's own `index.html` with status 200, while 400
  and 422 come through as JSON. A refusal check should therefore assert "no JSON data" and use an own-company control, never
  a bare status code.
- **Staff seats can't prove tenancy.** Every tenancy claim needs `is_eg_admin`/`is_admin` false and a positive control.
- **React re-renders overwrite custom ids.** Use React's own `«r..»` ids through XPath, or a `data-qa` attribute set right
  before the command.
- **Long waits go into the page.** A job polled with `window.__job` avoids the 120 s tool limit (the 110-preview sweep ran
  this way).

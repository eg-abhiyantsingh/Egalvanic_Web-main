# ZP-4671: how a user can select 1,000 assets once QR Labels stops preloading everything

- **Asked by:** Krunal on a call with the owner, 12 Oct 2026, about 13:08 IST. He is fixing ZP-4671: QR Labels downloads every asset before the page is usable.
- **Measured on QA:** "test site" `21bd10d4-cb0e-4e21-9722-9cd6219cedfc` (1,983 assets), adminqa seat, read-only API calls.

| Call | Result |
|---|---|
| `GET /api/lookup/v2/nodes/<site>?page=1&page_size=200` (today's loader) | 200 rows, 431 KB, about 1 s. `page_size` is capped at 200, so the whole site takes 10 calls and about 4.3 MB |
| `GET /api/lookup/v2/nodes/<site>?ids_only=true` | **all 1,983 ids in ONE call**, 85 KB, 0.5–1.1 s. Returns `{ids, total, limit: 5000, truncated}` |
| `...?ids_only=true&room_id=<room>` | 1,476 ids (one room), 64 KB, 0.47 s |
| `...?ids_only=true&search=panel` | 21 ids |
| `GET /api/lookup/v2/nodes/<site>/filter-options` | 17 KB, 0.8 s. Rooms with `label` "Building > Floor > Room" and `count`, plus classes with counts |

## Suggested flow
1. Open the page with `filter-options` (one call). Build the location tree with counts and show only the first page of rows.
2. "Select all", or ticking a building, floor or room, makes one `ids_only` call with the same filters (`room_id`, `search`). The selection is the returned id list, so "1,000 selected" is exact immediately.
3. Load more rows only as the user scrolls, 200 per page at most.
4. Fetch full rows for the selected ids only on **Continue**, because label stock, the designer and print need names, codes and locations.

## Backend gaps for this flow
- No server-side filter for "No QR code yet" or "Hide already labeled". The banner's "N without a code" needs one, or `ids_only` must also return `has_code` and `last_labeled`.
- No "No location" (unassigned) bucket in `filter-options` and no matching filter.
- `ids_only` stops at 5,000 (`truncated: true`). Larger sites need room-by-room selection or paging of ids.
- Edit codes saves one request per asset (ZP-4672), so 1,000 assets means 1,000 parallel calls. A batch save is needed.
